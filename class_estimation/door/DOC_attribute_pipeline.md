# 도어 속성 기반 분류 파이프라인 (Attribute Pipeline)

작성: 2026-07-07

## 1. 배경 — 왜 만들었나

기존 8-way CNN(RGBE NoAux)은 실험실 데이터에서 100%였지만 **현장(ZED 2i) 데이터에서
14.1%로 붕괴**했다 (정정 라벨 기준 그룹 49.9% / 클래스 0.2%, N=10). 원인 분석 결과:

- CNN은 클래스당 실물 샘플 1개를 "지문"처럼 암기 → 같은 클래스라도 다른
  실물/사양의 부품을 전혀 인식하지 못함 (대차 세션 E30_E38_RH를 E25_LH_FRT로
  99.9% 확신 오분류).
- 극단 RGB 증강 벤치마크(92~94%)는 이 현장 붕괴를 전혀 예측하지 못했다 —
  증강은 같은 개체의 변형만 만들기 때문.

이에 따라 부품의 **설계 속성**(통풍구 슬롯 배치, 외형 치수)을 CAD에서 가져와
판별하는 파이프라인을 구축했다. 신규 리비전 대응이 재학습이 아니라 **STL 1개
추가**로 끝나는 것이 핵심 장점.

## 2. 판별 원리

CAD 분석으로 확정된 클래스 구조 (`attribute_models/class_spec.json`):

| 그룹 | 클래스 | bbox (mm) | 슬롯 수 | 판별 단서 |
|---|---|---|---|---|
| FRT | E25 / E30 / E38_LH_FRT | 828/869/916 × 1140 | 0 | 가로 폭 (41~47mm 간격) |
| RR | E25 / E30 / E38_LH_RR | 1141/1262/1456 × 1140 | 236/240/299 | 슬롯 밴드 배치 + 폭 |
| RH | E25_RH / E30_E38_RH | 1140×990 / 1191×1140 | 40/50 | 슬롯 밴드 + 폭 |

- 전 차종 공통으로 한 변이 1,140mm → 절대 치수 대신 **종횡비**를 쓰면
  카메라 내부 파라미터/스케일 오차에 불변 (ZED X mini ↔ 2i 호환 확인됨).
- 슬롯 개수의 정확한 카운팅은 불필요 — E25↔E30 RR은 4개 차이라 어차피 불가.
  그룹은 **배치(레이아웃)**, 그룹 내는 **종횡비**가 담당.

### 파이프라인 (2단계 + N프레임 집계)

```
카메라 프레임 (rgb + depth)
 └─ MobileSAM 도어 마스크
     └─ 렉티파이: depth 평면 피팅 → 정면 직교뷰 (2mm/px)
         ├─ [그룹] U-Net 통풍구 세그멘테이션 → CAD 슬롯 템플릿 매칭(방향 정합)
         └─ [차종] PCA 실측 종횡비 × 템플릿 점수 결합
              score(c) = (템플릿IoU + 0.01) × exp(-|log(aspect/center_c)|/0.05)
                         └ FRT는 템플릿 점수가 전부 ~0이라 자동으로 종횡비 지배
 N프레임(기본 10) 집계: 그룹 다수결 + 종횡비 중앙값 → 최종 클래스
```

### 학습 라벨은 전부 자동 생성 (수작업 라벨링 0장)

각 학습 이미지를 렉티파이·축정렬해 CAD 템플릿 프레임에 정합하면, **CAD 슬롯
마스크가 그대로 픽셀 라벨**이 된다 (클래스당 라벨 1장 공유, 정합 IoU 중앙값
0.91~0.98, IoU<0.8은 자동 제외).

## 3. 검증 결과 (2026-07-07)

배포형 원시 경로, N=10 집계, 부트스트랩 2000회. (group% / class%)

| 모델 | datasets | datasets_aug | datasets_aug2 | 현장(정정 라벨) |
|---|---|---|---|---|
| 레거시 CNN (RGBE NoAux) | 100 / 100 | 100 / 99.9 | 100 / 100 | 49.9 / 0.2 |
| 속성 파이프라인 (U-Net v1) | 98.3 / 94.9 | 98.8 / 96.8 | 90.9 / 88.8 | 100 / 21.8 |
| **속성 파이프라인 (U-Net v2)** | **100 / 97.2** | 98.9 / 96.9 | **99.9 / 97.5** | **100 / 20.5** |

- U-Net v2 = 원본+aug+aug2 3배 학습(라벨 자동 전이) + 현장풍 증강. 극단 텍스처
  취약(aug2) 해소.
- **현장 그룹 100%**: 대차 세션은 세션 최종 판정 정답. 실제로 대차 세션의
  라벨 오류(E25_RH로 잘못 기록)를 파이프라인 예측이 먼저 잡아냈다.
- 현장 클래스 ~21%의 원인은 알고리즘이 아니라 **촬영 프로토콜**(아래 §5):
  지그 세션은 클램프·이중 도어로 마스크 오염, 기존 11장은 도어가 프레임에 잘림.

### 개발 중 확인된 함정 (재현 방지용)

1. STL 투영에 `cv2.fillPoly` 금지 — even-odd 규칙으로 판금 앞뒷면이 상쇄됨.
   삼각형별 `fillConvexPoly` OR 누적 사용 (10_generate_cad_templates.py).
2. 렉티파이 스캐터 노이즈 → medianBlur(3) + 통풍구 소형 성분(<3cm²) 제거
   필수. 없으면 FRT(솔리드)에서 가짜 통풍구 검출.
3. 템플릿 매칭 시 예측 맵과 템플릿의 가로/세로 방향을 맞춰 **90° 회전 후**
   리사이즈. 왜곡 리사이즈 시 세로형 클래스(FRT, E25_RH)가 무너짐 (83→98%).
4. 정사각형에 가까운 도어(E25_LH_RR, 비율 1.001)는 종횡비 측정이 1.07쯤으로
   상향 편향됨(노이즈가 최장/차장 정렬로 벌어짐) → CAD 값이 아니라 **실측
   캘리브레이션 중심(aspect_center)**을 판정 기준으로 사용.
5. depth 절대 치수는 카메라 불일치 시 수 배 오차 가능 — 반드시 비율만 사용.

## 4. 파일 구성

| 파일 | 역할 |
|---|---|
| `attribute_utils.py` | 공용 모듈: 렉티파이/축정렬/U-Net/템플릿 매칭/N프레임 판정 |
| `attribute_models/class_spec.json` | 클래스 스펙 (bbox, 종횡비 중심, 슬롯 수, 판정 파라미터) |
| `attribute_models/cad_templates.npz` | CAD 투영 템플릿 (실루엣+슬롯, 2mm/px) |
| `attribute_models/vent_unet2.pth` | 통풍구 세그멘테이션 U-Net v2 |
| `10_generate_cad_templates.py` | STL → 템플릿/스펙 재생성 |
| `11_generate_vent_labels.py` | 학습 라벨 자동 생성 (CAD 정합) |
| `12_train_vent_unet.py` | U-Net 학습 |
| `13_evaluate_attribute_pipeline.py` | 평가 (datasets/aug/factory, N프레임 부트스트랩) |

재현 순서: `10 → 11(원본·aug·aug2 각각) → 12 → 13`.

## 5. 현장 촬영 프로토콜 (정확도 전제 조건)

1. **도어 전체가 프레임 안에** 들어오게 촬영 (잘리면 종횡비 측정 불가).
2. **한 프레임에 도어 1장만** (지그 위 이중 배치 금지).
3. 클램프·지그 바 등 **도어 위 가림 최소화** (마스크 오염 → 종횡비 왜곡).
4. 도어당 **10프레임 이상** 취득 (N=10 집계가 판정 단위).
5. 평가용 취득 시 폴더(클래스) 라벨을 슬롯 수·치수로 재확인
   — 판별 기준: `datasets_factory/README.md` 참조.

## 6. 신규 부품/리비전 추가 절차

1. 해당 리비전의 STL을 `cad/door_stl/`에 추가 (양산 리비전과 일치 필수).
2. `python 10_generate_cad_templates.py` — 템플릿/스펙 자동 갱신.
3. (선택) 실물 이미지 확보 시 `11 → 12`로 U-Net 갱신, `13`으로
   aspect_center 재캘리브레이션.
