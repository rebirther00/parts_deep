# 굴착기 도어 CAD 합성 데이터 분류 전략

## 1. 문제 정의

### 대상 부품
- 굴착기 도어 **8종** (E25, E30, E38 모델 × FRT/RR/RH 위치)
- Isaac Sim으로 USD 모델에서 합성 데이터 생성 (클래스당 500장, 총 4,000장)

### 핵심 난이도
- 모든 도어의 **높이(1,140mm)와 두께(~72mm)가 동일**
- **가로 폭만 차이** (828mm ~ 1,456mm)
- 같은 타입(FRT끼리, RR끼리) 내에서는 형태/텍스처도 매우 유사

### 8개 클래스 크기 및 종횡비

| 클래스 | 가로(mm) | 세로(mm) | 종횡비(W/H) | 서브그룹 |
|--------|:--------:|:--------:|:-----------:|:--------:|
| E25_door_LH_FRT | 828 | 1,140 | 0.726 | FRT |
| E30_door_LH_FRT | 869 | 1,140 | 0.762 | FRT |
| E38_door_LH_FRT | 916 | 1,140 | 0.803 | FRT |
| E25_door_RH | 990 | 1,140 | 0.868 | RH |
| E25_door_LH_RR | 1,141 | 1,140 | 1.001 | RR |
| E30_E38_door_RH | 1,191 | 1,140 | 1.045 | RH |
| E30_door_LH_RR | 1,262 | 1,140 | 1.107 | RR |
| E38_door_LH_RR | 1,456 | 1,140 | 1.277 | RR |

인접 클래스 간 종횡비 최소 차이: **약 4~5%**

---

## 2. 서브그룹 분석

### 그룹별 시각적 특징

- **FRT (앞문)**: 평평한 패널, 메시/그릴 없음, 소형 사각 컷아웃
- **RR (뒷문)**: 다이아몬드 메시/그릴 패턴, 환기구 구조
- **RH (우측)**: 별도 패턴

### 분류 난이도

- **쉬움**: FRT vs RR vs RH (텍스처/패턴 차이가 확연함)
- **어려움 (핵심 과제)**:
  - E30_FRT vs E38_FRT: 폭 차이 47mm (5.4%), 형태 거의 동일
  - E25_RR vs E30_RR: 폭 차이 121mm (10.6%), 유사한 메시 패턴
  - E30_RR vs E38_RR: 폭 차이 194mm (15.4%), 유사한 메시 패턴

## 3. 운용 환경 조건

- **촬영 방식**: 작업자가 핸드헬드 카메라로 촬영 (거리/각도 가변)
- **우선 순위**: 정확도 최우선 (파이프라인 복잡도는 허용)
- **핵심 물리적 원리**: 종횡비(W/H)는 카메라 거리에 무관하게 보존됨
  - 카메라가 1m에서 찍든 3m에서 찍든, 도어의 가로/세로 비율은 동일
  - 단, 극단적 perspective 왜곡(비스듬한 각도)에서는 변형될 수 있음

## 4. 현재 방식의 한계 분석

### 기존 파이프라인 (`02_door_cad_classification_5090.py`)

- **모델**: ResNet18 (ImageNet pretrained) + FC Head (Dropout → 256 → 8 classes)
- **전처리**: `Letterbox Resize(장변 224px) + 중앙 배치 패딩(224×224)` (종횡비 보존)
- **증강**: RandomRotation(5°), ColorJitter, HorizontalFlip 제거
- **렌더링 해상도**: 1920×1080 (16:9)

### 한계점

1. **해상도 부족**: 224px에서 4~5% 종횡비 차이 = 약 10px 차이 → CNN이 감지하기 어려움
2. ~~**렌더링 정규화**: Isaac Sim에서 AABB 기반 카메라 거리 조정으로 모든 도어가 프레임에서 비슷한 크기로 보임 → 크기 차이 신호 약화~~ → **해결 완료** (아래 4.1 참조)
3. **모델 용량**: ResNet18은 fine-grained 분류에 최적이 아님

### 4.1 카메라 거리 문제 및 해결 (2026-03-23)

**문제**: 기존 카메라 파라미터에서 Z축 최소 거리가 `cam_min * 0.7`로 설정되어 있어 카메라가 너무 가까이 접근하여 도어 전체가 프레임에 잡히지 않는 이미지가 다수 발생.

**수정 내용** (`01_generate_door_cad_dataset.py`):

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| fill 비율 | `/0.8` (80% 채움) | `/0.6` (60% 채움) |
| cam_min | `min_cam * 0.95` | `min_cam * 1.2` |
| cam_max | `min_cam * 1.15` | `min_cam * 1.6` |
| Z축 최소 | `cam_min * 0.7` | `cam_min` (그대로) |
| lateral_x | `cam_max * 0.27` (±15°) | `cam_max * 0.15` (±8°) |
| lateral_y | `cam_max * 0.20` | `cam_max * 0.10` |
| init_cam | `min_cam * 0.9` | `cam_min * 1.2` |

**효과**: 도어가 프레임의 약 50~70%를 차지하면서 전체 형태가 항상 완전히 보이고, 종횡비 차이가 명확히 드러남. 데이터 재생성 필요.

## 5. 추천 접근법

### 접근법 A: 고해상도 + 강력한 모델 (가장 직접적)

- **입력 해상도를 384~448로 높임**: 종횡비 차이가 더 많은 픽셀로 표현
- **모델 업그레이드**: EfficientNet-V2-S 또는 Swin Transformer V2
  - 프로젝트에 이미 Swin V2 코드 있음 (`pos_estimation/13_depth_based_pose_v4.py`)
  - Self-attention이 전체 형태의 비율 파악에 유리

**장점**: 구현 변경 최소, 기존 파이프라인 구조 유지  
**단점**: 학습/추론 시간 증가

### 접근법 B: 2단계 계층적 분류 (정확도 극대화)

```
입력 이미지
    ↓
[1단계] FRT / RR / RH 분류 (텍스처 기반, 거의 100% 정확도 기대)
    ↓
[2단계-FRT] E25 / E30 / E38 분류 (종횡비 + 미세 디테일)
[2단계-RR]  E25 / E30 / E38 분류 (종횡비 + 메시 밀도 차이)
[2단계-RH]  E25 / E30_E38 분류 (종횡비 차이)
```

- 1단계: 쉬운 문제 → 높은 정확도
- 2단계: 각 서브그룹 전용 모델 → 미세 차이에 집중 가능
- 각 단계에서 더 쉬운 문제를 풀게 되므로 전체 정확도 상승

**장점**: 각 단계가 단순한 문제, 해석 가능  
**단점**: 모델 3~4개 관리 필요

### 접근법 C: 데이터 증강 정밀 제어

- `RandomRotation`을 과하게 하면 종횡비 단서 훼손 → 최소화 (현재 5°는 적절)
- **RandomPerspective** 적당히 추가: 핸드헬드 환경 시뮬레이션
- **Scale Jittering** 추가: 다양한 촬영 거리 효과
- HorizontalFlip 제거 유지 (LH/RH 구분을 위해)

### 부적합한 접근법 (제외)

| 접근법 | 제외 이유 |
|--------|-----------|
| 카메라 거리 고정 렌더링 | 핸드헬드 환경과 불일치 (Sim-to-Real Gap) |
| CNN + 종횡비 수치 입력 | 별도 물체 검출 파이프라인 필요, 복잡도 증가 |
| Letterbox 패딩만 | 정방형 입력 이미지에서는 효과 제한적 |

## 6. 실행 우선순위

### Phase 1: 빠른 베이스라인 확인
1. 현재 데이터(500장×8클래스)로 기존 ResNet18 학습
2. 혼동 행렬(Confusion Matrix) 분석 → 실제로 어떤 쌍이 혼동되는지 확인
3. 이 결과가 개선 방향의 근거가 됨

### Phase 2: 모델/해상도 개선 (접근법 A)
1. 입력 해상도 224 → 384로 변경
2. ResNet18 → EfficientNet-V2-S 또는 Swin V2로 교체
3. 동일 데이터로 학습 후 혼동 행렬 비교

### Phase 3: 계층적 분류 (접근법 B, 필요시)
1. Phase 2에서 특정 서브그룹 내 혼동이 해결되지 않으면 적용
2. 1단계 분류기 + 서브그룹별 2단계 분류기 구현

### Phase 4: 데이터 증강 고도화 (접근법 C)
1. RandomPerspective, Scale Jittering 추가
2. 실제 촬영 이미지와의 도메인 갭 최소화
