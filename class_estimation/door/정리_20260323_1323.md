## 3. 진행 과정 및 문제 해결

### 3-1. CAD 변환 (STP → STL → USD)

- **문제**: Isaac Sim이 STP 직접 변환 미지원 (`UNSUPPORTED_IMPORT_FORMAT`)
- **해결**: 사용자가 수동으로 STP → STL 변환 후, STL → USD 변환 스크립트 작성
- **문제**: USD 파일 단위 불일치 (mm를 m로 해석 → 1000배 크기)
- **해결**: `fix_usd_units()` 함수로 scale(0.001) + translate(-center) + metersPerUnit=1.0 적용
- **최종**: 사용자가 Isaac Sim GUI에서 직접 USD 파일 생성 (m 단위, 축 통일)

### 3-2. 합성 데이터 생성 - 검은 이미지 문제

- **1차 원인**: 단위 스케일 문제 → USD 변환 수정
- **2차 원인**: 조명이 카메라 반대편에 위치 → 같은 방향으로 재배치
- **3차 원인**: Material 미지정 → UsdPreviewSurface 기본 material 자동 생성
- **4차 원인**: 바닥/벽이 카메라를 가림 → 장면 구성 전면 재설계 (+Z 카메라 방향)
- **최종**: 정상 이미지 생성 확인 후 클래스당 500장 생성

### 3-3. 학습 - E30/E38 LH_FRT 혼동 문제

**1차 학습** (ResNet18 + 224px, 카메라 ±45°)
- 전체 정확도: 87.62%
- E30_LH_FRT: 58%, E38_LH_FRT: 58% (서로 혼동, 시소 현상)

**2차 학습** (ResNet50 + 448px로 변경)
- 오히려 악화: E30_LH_FRT: 11%, E38_LH_FRT: 92% (한쪽 편향)
- 원인: 모델이 아닌 데이터 품질이 핵심 문제

**3차 학습** (데이터 재생성 + 모델 원복)
- 카메라 각도: ±45° → ±15° (정면 위주, 가로 폭 차이 보존)
- 카메라 거리: 0.9~1.5 → 0.95~1.15 (일관된 프레이밍)
- 바닥 밀착: 그림자 제거로 윤곽선 명확화
- 조명 랜덤화 범위 축소
- **결과: E30_LH_FRT: 95%, E38_LH_FRT: 93%로 대폭 개선**

### 3-4. 크로스 도메인 평가 (합성 모델 → 실물 이미지)

실물 데이터 현황 (3클래스만 확보):
- E25_door_LH_FRT: 134장
- E30_door_LH_FRT: 163장
- E38_door_LH_FRT: 153장

**결과: 전체 정확도 36.44% (절망적)**

| 클래스 | 정확도 | 분석 |
|--------|--------|------|
| E25_door_LH_FRT | 1.49% | 129장이 E30_FRT로 오분류 |
| E30_door_LH_FRT | 98.16% | 거의 모든 이미지를 이 클래스로 예측 |
| E38_door_LH_FRT | 1.31% | 148장이 E30_FRT로 오분류 |

**원인 분석 (Domain Gap)**:

| 항목 | 합성 이미지 | 실물 이미지 |
|------|-------------|-------------|
| 색상 | 흰색/파스텔 배경 | 금속 은회색, 녹, 반사광 |
| 질감 | 매끈한 UsdPreviewSurface | 스크래치, 용접자국 |
| 배경 | 단색 바닥 + 벽 | 콘크리트 바닥, 공장 환경 |
| 조명 | 균일한 돔+구체 | 형광등 반사, 그림자 |
| 구도 | 정면 위(+Z) | 비스듬한 각도, 다양한 거리 |
| 디테일 | 힌지/볼트 없음 | 실제 부품 부착 |

## 5. 핵심 교훈

1. **합성 데이터만으로는 실물 추론이 어렵다** - Domain Gap이 크면 36% 수준
2. **데이터 품질 > 모델 크기** - ResNet50+448px로 올려도 데이터가 나쁘면 악화
3. **카메라 각도 제한이 형태 유사 부품에 효과적** - ±45° → ±15°로 줄여 95%까지 개선
4. **그림자 제거**가 윤곽선 기반 분류에 도움
5. **Fine-tuning (도메인 적응)** 이 합성→실물 격차 해소의 핵심 전략
