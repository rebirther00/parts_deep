# 레이더 옵션 규칙 v2 (2026-11-06)

사용자 지적("레이더는 홀 2개만 있으면 O 로 처리하는 것 아닌가")을 확인해 수정한 기록. 코드: `partno/radar_check.py`(`RULE_VERSION='2026-11-06'`), `07_factory_infer.py` 0.2.0.

## 확인 결과

- 피크 경로(`radar_from_peaks`)는 이미 CAD 위치(≤40mm)·간격(91.6±20mm)을 검사하고 있었고, 수집 데이터 레이더 없음 1,680프레임에서 피크 2개(≥0.30)가 뜬 프레임은 0.
- 현장 오판 2건(11/4 `20261104/s_075733`·`s_151538`, E25_door_RH, 브래킷 없음, VLM 2차 의견 X)은 **규칙 경로**: 보강재 위에 놓인 바 클램프·렌치가 CAD 홀 자리의 어두움(0.25~0.28)과 depth 높이(39~45mm)를 흉내내 "점수 ≥0.08 & 높이 ≥37 → 레이더" 조건을 통과, unsure 를 뺀 4/4·5/5 투표로 O 잠금. 브래킷 피크는 도어 밖 지그 위 둥근 물체(0.21~0.33).
- 추가 발견: 피크 역투영의 radial 시차 근사(광축 ⟂ 도어 가정)가 도어 기울기(8~9°)를 무시 → 피크-CAD 거리가 카메라 재장착(9/22) 전후·세션별로 10~33mm 요동. E38_LH_RR 은 42mm 로 허용 40 을 넘어 늘 규칙 경로로 떨어지고 있었다(결과는 우연히 맞음).

## 수정

1. **3D 프레임**: depth 평면 + 6점으로 도어 XY↔카메라 3D 아핀(M)과 평면 법선(n)을 만들고, 브래킷 판 위 점은 법선 방향으로 70mm 띄워 투영/역투영(`door_frame`/`to_px`/`to_door`). depth 없으면 radial 근사 폴백.
2. **피크 경로 허용치** 40mm/±20 → **25mm/±12** (아래 분포 기준).
3. **규칙 경로 O 전제**: (a) 브래킷 피크(≥0.12) 하나라도 CAD 홀 ≤25mm(`support`), (b) 판 안쪽 7×3 격자(홀 주변 제외) depth 중앙값 ≥37mm(`h_plate`). 공구는 둘 다 못 넘어 미정.
4. DB 검사(`run_session`)·오프라인 품번 도구(`infer_partno.py`)도 서비스와 같은 하이브리드(`decide_option`)로 통일. `result.json` 에 `radar_rule`·`option_frames`·`frames[].option` 기록.
