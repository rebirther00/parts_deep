## 9. AI 모델 3계열 개요
**메시지**: 형상 암기형 CNN → CAD 설계 속성 기반 판정으로 전환, 홀 판별기가 현재 1순위
| 모델 | 방식 | 실험실 | 현장 |
|---|---|---|---|
| ① CNN 분류 | ResNet18, RGB+Edge 4채널 | 100% | 14%(개체 암기로 붕괴) |
| ② CAD 속성 파이프라인 | MobileSAM + 통풍구 U-Net + 종횡비 | 99.2~99.7% | 그룹 100% |
| ③ 홀 랜드마크 판별기 | CNN 홀 6점 검출 + CAD 치수 대조 | test 100%, 전체 99.0% | 194/194 (100%) |
- 판정 정책: ③ 1순위 → ②가 그룹 제약·폴백 → 불일치 시 보류(conflict). 실시간 서버 통합 완료
- 노트: "왜 실험실 100%가 현장 14%였나" 질문 대비 — 클래스당 실물 1개의 외관을 지문처럼 암기, 증강 강건성도 이를 예측 못함 → 설계 속성 기반으로 전환한 근거

## 10. 홀 랜드마크 판별기 — 원리
**메시지**: AI는 "홀 위치 검출"만, 판정은 설명 가능한 치수 비교
- 8종 모두 좌우 세로 프레임 끝에 동일 위치 Ø6mm 홀 한 쌍 → 거리 D = 도어 폭 − 106mm
- 8종 폭이 모두 달라 D만으로 구분(최소 간격 41mm), 홀 중심은 클램프·조명·녹에 무관
- CAD D vs 사람 라벨 실측 D: 8종 모두 ±7mm 이내
- 파이프라인: CNN 6점 검출(볼트홀 4 + 모서리 홀 2) → Depth 평면 피팅 → 평면상 거리 D(mm) → 기하 게이트 → CAD 최근접 → 10프레임 집계
- 시각: `report/hole_analysis/corner_marked_E25_door_RH.png`(CAD 홀 표시), `report/hole_analysis/samples/` 성공 예(파란 볼트홀·빨강/주황 모서리 홀·빨간 선 D), 8종 폭/D 표

## 11. 홀 랜드마크 판별기 — 학습 기법
**메시지**: 134장 소량 라벨로 픽셀 단위 검출기 학습
- 라벨: 자체 브라우저 도구(15_label_holes.py)로 134장 × 6점, 약 1시간. 층화 홀드아웃 27장 / 학습 107장
- 모델: ResNet18(ImageNet) + FPN 디코더, 1280×768 letterbox, stride-4 가우시안 히트맵(σ=2), 가중 MSE(양성 ×21), 5px NMS + 서브픽셀
- 증강: 회전 ±180°, 스케일 0.75~1.15, 이동, 플립, 밝기·대비, 블러 — 지그 위 임의 각도 대응
- 최적화: AdamW 1e-4, 3 epoch 워밍업 + 코사인, grad clip 1.0, FP32, 80 epoch (1차 OneCycle+FP16은 발산 → 폐기)
- 규칙 기반 검출(모폴로지·NCC)은 GT 대비 오검출 48~60%로 폐기 — "검출 정확도는 GT로 재야 한다"
- 시각: 라벨링 도구 화면, 학습 곡선(`report/hole_analysis/samples/` 학습 곡선 PNG)

## 14. 기존 기술 대비 개선점
**메시지**: 규칙 기반 Vision·일반 CNN의 한계를 설계 속성 기반으로 극복
- 규칙 기반(슬롯 카운팅·에지·템플릿): 조명·반사·녹에 따라 프레임별 편차 → CAD 정합 라벨로 학습한 세그멘테이션·학습 검출기로 안정화
- 일반 CNN 분류: 개체 재질·외관 암기 → 치수(종횡비·홀 거리) 입력으로 전환
- 라벨링 비용: 통풍구 픽셀 라벨 0장(CAD 자동 생성), 홀 라벨 134장, 분류 라벨은 촬영 시 버튼
- 설명 가능성: 판정 근거가 "실측 D = 1157mm ↔ CAD 1158mm"처럼 숫자로 제시됨

**메시지**: CAD만 있으면 판정 대상 추가, 재학습 불필요
- 속성 파이프라인·홀 판별기: CAD에서 판별 기준 자동 생성 → CAD가 있는 판금 부품에 적용 가능
- 신규 차종/리비전: CAD D 값 1개 추가(홀 판별기), 스펙 재생성(속성) — 픽셀 라벨링·재학습 불필요. 단 실물 수십 프레임으로 기준값 1회 보정
- 한계: 기존 클래스와 홀 거리 ~40mm/종횡비 ±5% 이내면 구분 불가, 신규 클래스 추가 실증은 미수행
- CNN: 라벨 데이터만 있으면 재학습으로 적용

## 16. AI 인프라
**메시지**: 온프레미스 3거점, 수집→학습→추론 자동화
- 학습 PC: RTX 5090 32GB, Core Ultra 9 285K, 64GB — 학습·평가·추론 서버·DB
- 현장 엣지: ZED Box(Jetson Orin NX 16GB) — 수집 장비, 추론 실측·최적화 진행
- 저장: NAS DS1522+ 20TB(정본)
- 네트워크: 사이트 간 VPN(tailscale/ZeroTier), 현장 LTE
- SW: 수집 서비스 자동화, NAS 자동 업로드, 메타데이터 DB·웹 열람, 재현 가능한 학습·평가 파이프라인(시드·분할 고정, 결과 자동 기록), 실시간 추론 서버
- 최종 추론 위치(엣지 vs 서버)는 최적화 실측 결과로 결정
- 시각: 인프라 구성도

## 18. 과제 목표 대비 현황과 남은 과제
**메시지**: 인식률 99% — 실험실 달성, 현장 3종 100%; 5종 현장 데이터 확보가 마지막 관문
| 항목 | 상태 |
|---|---|
| 실험실 인식률 99% | 달성 (99.0~100%) |

| 현장 상시 판정 | 수집 단계, 판정은 세종 서버에서 오프라인 |

## 19. 예상 질의 응답 (백업 슬라이드)
- 왜 실험실 100%인데 현장 14%? → 개체 암기, 그래서 설계 속성 기반 전환
- 라벨링 비용? → 통풍구 0장(CAD 자동), 홀 134장, 분류는 버튼
- 신규 차종? → CAD D 1개 추가, 재학습 불필요(단 40mm 이내면 구분 불가)
- 카메라 바뀌면? → 종횡비·보정계수 설계, K_DEPTH 라벨 10장으로 캘리브레이션
- 판정 못 하면? → 기하 게이트로 보류, 사람 확인. 현장 보류 0%(빈 지그만)
- 위치 정도 3mm? → 본 업무 외. 홀 거리 오차 20~58mm는 종류 판별용이지 위치 측정용 아님
