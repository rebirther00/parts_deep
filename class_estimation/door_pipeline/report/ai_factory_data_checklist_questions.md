## 1. 데이터 종류 및 확보

1. AI 자율제조에 필요한 제조 데이터가 잘 정의되어 있는가?

   **답변**: 도어 용접 공정의 부품(도어) 종류 자동 인식을 위한 데이터로, **RGB 이미지 + Depth 이미지 쌍**을 정의하여 사용 중.
   - RGB: PNG, 1920×1200(HD1200) / Depth: PNG uint16, mm 단위(ZED NEURAL depth)
   - 클래스: 차종 3종(E25/E30/E38) × 도어 위치(LH FRT / LH RR / RH) = **8클래스** (E30·E38 RH는 동일 부품이라 1클래스로 통합)
   - 판별 기준을 CAD(STL)에서 추출해 스펙 파일로 관리: ① 외형 치수·통풍구 슬롯 수·배치 ② **모서리 프레임 홀 간 거리 D 표**(8종의 도어 폭이 모두 달라 D = 도어 폭 − 106mm 만으로 구분 가능, 최소 간격 41mm)
   - 부수 데이터: 세션별 `meta.json`(클래스·시각·저장 쌍 수·종료 사유), 전체 버튼/세션 이벤트 로그 `events.jsonl`(라벨 정정 추적용)

2. 실라인에서 획득되는 제조 데이터 스펙(샘플링 주기, 속도, 통신방법 등)은 잘 정의되어 있는가?

   **답변**: 경주 공장 용접 라인에 무인 수집 시스템 **정식 설치·가동 중(2026-08-27~)**. 스펙은 운영 문서(`DOC_factory_collect.md`)로 정의.
   - 장비: ZED X mini(스테레오 깊이 카메라, GMSL) + ZED Box(Jetson Orin NX 16GB) + LTE 라우터 + 16" 터치모니터
   - 샘플링: 취득 시작 후 2초 워밍업(저장 안 함) → **2초에 1장** RGB/Depth 쌍 저장 → 작업자 종료 버튼(미조작 시 300초 후 자동 종료)
   - 통신: 세션 종료 즉시 rclone으로 세종 NAS 자동 업로드 + cron 5분 주기 보완(`.uploaded` 마커로 중복 방지, 로컬 원본 보존). 원격 모니터링 VPN(tailscale 주 / ZeroTier 예비)
   - 작업자 조작은 버튼 3단계뿐: 도어 종류 버튼 → [취득 시작] → 용접 후 [취득 종료]. A4 1장 사용 안내문 현장 게시

3. AI 자율제조를 위해 부족한 데이터 셋이 무엇인지? 확보 계획은?

   **답변**: **현장(경주) 데이터 부족이 핵심 과제** — 실험실 데이터만으로 학습한 CNN이 현장 개체에서 붕괴(14.1%)하는 것이 확인되어 현장 데이터 확보를 최우선으로 진행.
   - 진행 경과: 2026-04 수동 취득(78장) → 2026-07-29 수집 장치 시험 운영 → **2026-08-27 정식 설치·가동**
   - 현황(8/31 기준): **8종 중 7종, 31세션 2,708쌍** 확보. 잔여 1종은 **E25 앞문(E25_door_LH_FRT)** — 생산 순서에 따라 유입되는 대로 수집
   - 운영: 세종에서 1일 2회 원격으로 신규 세션 확인 후 홀 판별기로 즉시 검증. 작업자 버튼 라벨과 AI 판정을 교차 확인(2026-08-10 라벨 오기를 AI 판정으로 검출·정정한 실사례 있음)

4. 어떤 제조 설비 또는 라인(테스트베드, 실운전라인 등)에서 제조 데이터를 취득하였는가?

   **답변**:
   - **실험실(세종 사무소)**: 실물 도어 8종을 ZED X Mini로 촬영 — 1,256장 (학습·평가용 기본 데이터)
   - **실운전라인(경주 공장 도어 용접 라인)**: 2026-08-27부터 무인 수집 시스템으로 취득 중 (이전 이력: 2026-04 ZED 2i 수동 취득 78장)

5. AI 모델을 구축하기에 지금까지 확보한 제조 데이터는 어느정도인가? (Raw, 레이블 기준 수집현황)

   **답변** (2026-08-31 기준):

   | 데이터셋 | 출처 | 클래스 수 | 수량(RGB+Depth 쌍) | 라벨 상태 |
   |---|---|---|---|---|
   | 실험실 원본 | 세종, ZED X Mini | 8 (전부) | **1,256** | 클래스 라벨 100% |
   | 증강 1차 / 2차 | 원본 증강 | 8 | 1,256 / 1,256 | 동일 라벨 (강건성 평가 전용, 학습 금지) |
   | **소계(실험실)** | | | **3,768** | 전량 완료 |
   | 현장(무인 수집) | 경주, 2026-08-27~ | **7 / 8종** | **31세션 2,708쌍** | 작업자 버튼 라벨 + AI 판정 교차 검증 |

   - 분류 데이터는 폴더(클래스) 단위 라벨이므로 Raw = 라벨 수량.
   - 점 단위 라벨(홀 랜드마크): **134장 × 6점**(실험실 8종 118장 + 현장 16장), 자체 라벨링 도구로 약 1시간에 완료.
   - 학습 분할: train/val/test = 70/15/15를 분할 파일로 고정 저장, test는 학습 과정에서 완전 격리. 현장 데이터는 학습에 쓰지 않은 외부 평가셋.

6. 정의된 제조 데이터가 실시간(온프레미스, 클라우드 등)으로 확보되고 있는가?

   **답변**: **온프레미스로 실시간 확보 중.** 데이터 수집 시스템 가동 중(2026-08-27~)이며, 가동 시 세종 NAS로 자동 업로드되는 실시간 체계로 전환 완료.
   - 현장 ZED Box 로컬 저장 → 세션 종료(`finished: true`) 시 NAS 자동 업로드 → 학습 PC는 NAS를 정본으로 메타데이터를 DB에 인덱싱
   - 수집 서비스는 systemd로 부팅 자동 시작·장애 시 5초 후 재시작. 클라우드 미사용

7. (옵션) 인스트럭션 셋 데이터(레이블링 외 다양한 지식 포함 데이터셋)를 제공 가능한가?

   **답변**: 도어 인식 결과(종류, 좌표, 판별 근거)를 CAD 스펙 정보와 연계하여 관리하고 있어, 인스트럭션 셋 데이터로 가공할 수 있는 기초 여건은 마련되어 있음. 다만 현재는 별도의 인스트럭션 셋 형태로 정리된 산출물은 없으며, 무인 수집 시스템을 통한 실환경 데이터 축적 이후 필요성을 검토할 예정.

## 2. 데이터 전처리

1. 취득되는 제조 데이터 중 불필요 데이터를 정의하고 있는가?

   **답변**: 정의하여 처리 중.
   - 취득 단계: 카메라 안정화(워밍업 2초) 구간 저장 제외, 실험실 취득 시 블러 점수(Laplacian) 임계값 미만 프레임 제외
   - 학습 단계: CAD 정합 불량(IoU<0.8) 이미지 자동 제외, **한 프레임에 도어 2장은 학습 미사용**, Unknown 라벨 세션 학습 미사용
   - 판정 단계: **기하 게이트**가 판정 불가 프레임을 "보류"로 분리(오판과 구분) — 도어가 없는 빈 지그 9장이 전량 보류 처리된 것이 정상 동작 사례

2. 제조 데이터 내 몇 종의 전처리 기법이 활용되고 있는가?

   **답변**: 모델별로 다음 기법 사용.
   - CNN 분류: 깊이 기반 **Edge 채널 합성(RGB+Edge 4채널)**, 448×448 리사이즈, 정규화, 학습 시 온라인 증강
   - 홀 판별기: 원본 RGB를 **1280×768 letterbox**(비율 유지) + ImageNet 정규화. 학습 증강은 도어가 지그에 임의 각도로 놓이는 점을 반영해 **회전 ±180°**·스케일·이동·플립·밝기/대비·블러의 임의 아핀. Depth는 CNN 입력이 아니라 검출 후 거리 계산에만 사용
   - 오프라인 증강 데이터(1·2차)는 학습이 아닌 **강건성 평가 전용**으로 규정

3. 저장할 제조 데이터 표준 형태가 정의되었는가?

   **답변**: 정의 완료·운영 중.
   ```
   <날짜>/<도어종류>/s_<HHMMSS>/
     rgb_0000.png     # 1920×1200 PNG
     depth_0000.png   # uint16 PNG, mm
     meta.json        # 종류, 시각, 취득 간격, 세션 길이, 저장 쌍 수, 종료 사유
   events.jsonl       # 모든 버튼/세션 이벤트
   ```
   - 메타데이터 DB 스키마로 표준화되어 현장→NAS→학습 PC까지 동일 규칙 적용

4. 정의되었다면, 표준 형태로의 데이터 가공을 누가 하는가?

   **답변**: **수집 프로그램이 자동 수행.** 작업자는 도어 종류 버튼과 시작/종료만 조작하며, 파일명·폴더 구조·meta.json·이벤트 로그·NAS 업로드·DB 등록이 전부 자동. 수동 작업은 **홀 랜드마크 라벨 134장**(자체 브라우저 도구 — 6배 확대경·자동 진행·자동 저장, 약 1시간 소요)뿐.

5. 제조 데이터의 품질을 관리하고 있는가? (미싱 데이터, 정합성 체크 등)

   **답변**: 아래 항목을 관리 중.
   - **쌍 정합성**: RGB/Depth 항상 쌍으로 저장, `saved_pairs` 수 기록. DB 등록은 멱등(중복 방지)
   - **라벨 정합성**: 작업자 버튼 라벨을 AI 판정(홀 판별기)과 교차 검증 — 라벨 오기 검출·정정 실사례 확보. 세션 종료 시 종류 선택 자동 초기화로 연속 오기 방지
   - **업로드 누락**: `.uploaded` 마커 + cron 재시도 + 동기화 로그
   - **저장 무결성**: 세션 정상 종료 여부(`finished`, `stop_reason`) 기록
   - **장비 이상**: 카메라 grab 60회 연속 실패 시 자동 재연결, 디스크 여유 20GB 미만 시 화면 경고. 부팅 시 GPU 미준비·시계 미동기화도 자동 대응(운영 중 실제 발생·해결)

6. 데이터 품질 기준을 관리하고 있는가?

   **답변**: 문서화된 기준으로 관리.
   - 촬영 프로토콜: 도어 전체가 프레임 안(특히 힌지측 프레임 상단), 프레임당 도어 1장, 도어당 10프레임 이상
   - 학습 사용 기준: CAD 정합 IoU ≥ 0.8, 블러 임계값 통과
   - 평가 방법론: train/val/test 3분할 격리, 증강 데이터 학습 금지, 현장은 별도 외부셋 평가
   - 라벨 정정 규칙: 파일 이동 대신 meta/events/DB에 이력을 남기고 재배정

## 3. 데이터 저장 및 관리

1. 제조 데이터 저장소 및 스펙은 어떠한가?

   **답변**: **NAS(Synology DS1522+, 20TB)를 정본**으로 하는 3계층 온프레미스 구조.
   | 계층 | 위치 | 역할 |
   |---|---|---|
   | 현장 수집 장비 | ZED Box(경주 공장) | 1차 저장(원본 보존), 디스크 잔량 경고 |
   | **NAS(정본)** | 세종 | 세션 단위 원본 백업·공유(자동 업로드) |
   | 학습 PC | RTX 5090 워크스테이션(세종) | 학습용 데이터셋 + 메타데이터 DB(SQLite) |
   - 이미지는 파일시스템, 메타데이터는 DB로 관리하는 하이브리드 구조

2. 메타데이터는 AI 모델 개발에 충분히 자세한가?

   **답변**: 메타데이터 DB(9개 테이블)로 데이터→학습→평가 전 과정을 자동 기록.
   - 데이터: 데이터셋/클래스/이미지(경로·해상도·깊이 단위·블러 점수·출처·분할), 촬영 세션(카메라·모드·취득 간격·쌍 수·종료 사유)
   - 학습: 모델/학습 세션/에폭별 지표(아키텍처·하이퍼파라미터·GPU)
   - 평가: 평가 결과(정확도·혼동행렬·클래스별 결과) — 학습·평가 스크립트 실행 시 자동 기록

3. 제조 데이터 관리는 주기적으로 모니터링하는가?

   **답변**: 실시 중 — 세종에서 VPN으로 현장 키오스크 화면·프리뷰·당일 통계·로그를 **1일 2회** 원격 확인. DB는 자체 웹 도구로 브라우저 열람. 원격 불통 시 현장 전화로 전원 재투입 요청(재투입만으로 2~3분 내 자동 복구).

4. 데이터 관리 정책은 확장성(데이터·라인·사이트·모델 확장 등)이 있는가?

   **답변**:
   - 데이터 확장: 폴더 규칙 + 멱등 등록으로 신규 세션은 재스캔만으로 추가
   - 부품 확장: 신규 부품/리비전은 **CAD 파일 추가로 대응(재학습 불필요)** — 홀 판별기는 CAD에서 D 값 1개 추가로 판정 대상에 포함
   - 사이트/라인 확장: 설치 스크립트 1회 실행으로 배포, NAS 세션 트리 구조로 사이트 추가 가능
   - 모델 확장: DB가 아키텍처 무관 설계
   - 로드맵: 1단계 SQLite(완료) → 2단계 현장 서버 DB 연동 → 3단계 학습·평가 자동 기록(완료) → 4단계 PostgreSQL·다중 사용자

## 4. AI 모델

1. 본 사업을 위해 고려한 국내외 AI 레퍼런스 모델이 무엇인가?

   **답변**: **CNN 분류(ResNet18, RGB+Edge)** 및 **홀 랜드마크 검출기(ResNet18-FPN 히트맵) + CAD 치수 대조 판정기**.
   - CNN: ImageNet 사전학습 ResNet18에서 RGB / RGB-D / RGB+Edge 입력 변형을 비교 후 RGB+Edge 채택
   - 홀 판별기: ResNet18 인코더 + FPN식 디코더 + 히트맵 헤드로 홀 6점(래치 볼트홀 4 + 모서리 프레임 홀 2)을 검출하고, 판정은 학습이 아닌 **CAD 치수 대조**(두 모서리 홀 거리 D ↔ CAD D 표 최근접)로 수행

2. AI 모델을 적용해서 기대하는 벤치마크 성능에 대한 자료가 있나? (현재 수준)

   **답변**: 과제 목표 **인식률 99% 이상** — 실험실 조건 달성(CNN 100%, CAD 파이프라인 99.2~99.7%). 현장 조건은 현재 홀 판별기로 평가 진행 중.

   | 평가 세트 (홀 판별기, 라벨 학습분 제외) | 전체 | 판정 | 정답 | 판정 정확도 |
   |---|---|---|---|---|
   | 실험실 test 분할(격리) | 189 | 134 | 134 | **100%** |
   | 실험실 전체 | 1,162 | 814 | 806 | **99.0%** |
   | **현장 수집분(7종, 8/31 기준)** | 656 | **646** | **646** | **100%** |
   | 현장 빈 지그(도어 없음) | 9 | 0 | — | 전량 보류(오판 0) |

   - 현장 656프레임 중 보류 10건(빈 지그 9건 포함) — 기하 게이트가 판정 불가를 오판과 구분한 정상 동작
   - 홀 검출 정밀도(GT 대비): 홀드아웃 중앙값 1.0~1.4px(≈1.3mm/px), 오검출(>20px) 0%
   - 실험실 보류 ~30%는 도어를 꽉 채워 찍은 사무실 프레이밍(홀이 프레임 밖) 때문이며, 카메라가 고정된 현장에서는 빈 지그 외 보류가 거의 없음

3. 개발한 AI 모델을 적용해서 기대하는 검증 시나리오가 있는가?

   **답변**: 3단계 평가 체계로 1차년도 진행 — ① 실험실 시험셋(세션 단위 70/15/15 분할, 학습에서 격리) → ② 증강 강건성(증강 데이터는 학습 금지·평가 전용) → ③ 현장 외부셋 평가.
   - 현장 데이터는 학습·라벨 어디에도 쓰지 않은 완전한 외부셋(라벨에 사용한 16장은 판정 평가에서 제외)
   - 리플레이 모드로 현장 세션을 재생하여 실시간 판정 로직과 동일 조건 검증 가능

4. 개발된 AI 모델이 동일 업종, 다른 공정에 적용/확장이 가능한가?

   **답변**: 현재 모델은 8종 도어 인식에 특화되어 있으나, RGB+Depth 기반 객체 인식 구조 및 CAD 속성 연계 판별 방식은 형상·치수 정보가 있는 타 부품 인식에도 동일한 방법론으로 확장 적용이 가능할 것으로 판단됨.
   - 신규 차종/리비전: CAD에서 D 값 1개 추가로 판정 대상 포함(픽셀 라벨링·재학습 불필요), 실물 수십 프레임으로 기준값 1회 보정
   - 다만 현재까지 타 부품·공정 적용 실적은 없음

5. AI 모델 개발에 활용된 알고리즘 등은 무엇이고 성능은 어느정도인가?

   **답변**:
   - **CNN 분류**: ResNet18(ImageNet 사전학습), RGB+Edge 4채널 448×448. 실험실 test 100% — 다만 실물 개체 외관을 암기하는 특성으로 현장 개체에서 14.1%로 저하되어, 현장 판정은 아래 홀 판별기로 전환
   - **홀 랜드마크 판별기**: ResNet18-FPN 히트맵으로 홀 6점 검출(홀 단계 41ms/프레임, RTX 5090) → Depth로 도어 평면 피팅 후 두 모서리 홀의 mm 거리 D 산출 → 기하 게이트(볼트홀 4개가 157×96mm 기준 사각형을 이뤄 검출 결과를 자체 검증) → CAD D 표 최근접 판정 → 10프레임 중앙값 집계. **현장 판정 100%**(646/646)
   - 판정 근거가 "실측 D 1157mm ↔ CAD 1158mm"처럼 숫자로 제시되어 설명 가능

6. AI 모델의 지속적인 개선을 위한 프로세스는 마련되어 있는가?

   **답변**: 학습·평가 전 과정을 스크립트화(시드·분할 고정으로 재현 가능)하고 결과를 DB에 자동 기록해 모델 간 비교 가능. 현장 무인 수집→NAS→DB 인제스트의 신규 데이터 상시 유입 경로 구축 완료. 원리·검증 수치·촬영 프로토콜·리비전 추가 절차 문서화.

7. AI 모델을 활용하여 기존 기술 대비 개선한 점은 무엇인가?

   **답변**: 기존에는 작업자가 육안으로 도어 종류를 확인·분류하여 작업 속도·정확도가 숙련도에 좌우되는 한계가 있었음. 본 과제에서는:
   - RGB+Depth 영상 기반 AI 인식과 CAD 속성 연계 판별로 도어 종류를 **자동·정량적으로 판별**하는 가능성을 실험실 조건에서 확인
   - **판별 근거를 치수·형상 데이터로 추적**할 수 있는 구조 확보(블랙박스 분류가 아닌 실측 D ↔ CAD D 대조)
   - 형상 암기형 CNN의 현장 한계(14.1%)를 홀 검출 + CAD 치수 대조로 극복(현장 판정 100%)
   - 라벨 비용 최소화: 점 라벨 134장·약 1시간, 신규 클래스 추가 시 재학습 불필요
   - AI가 사람의 라벨 오기를 검출·정정한 실사례 확보

8. AI 모델의 제조 현장 적용을 통해 얻은 성과는 무엇인가?

   **답변**: 경주 공장 용접 라인에 무인 수집 시스템 설치·가동(2026-08-27~) 및 작업자 설명서 배포. 수집 데이터에 대한 정량 검증 완료 — **2026-08-31 기준 판정 646/646 정답**, 도어가 없는 빈 지그 9장은 전량 보류(오판 0)로 정상 동작 확인. (판정은 현재 세종 학습 PC에서 세션 리플레이로 수행, 현장 상시 판정은 엣지 배포 후)

9. 지속적인 AI 모델의 성능 개선을 위한 계획이 있는가?

   **답변**:
   ① 잔여 1종(E25 앞문) 현장 수집으로 **8종 검증 완결**
   ② 카메라 실측 캘리브레이션 반영으로 거리 측정 정밀화
   ③ 엣지(Jetson) TensorRT 배포로 취득 세션마다 자동 판정·DB 기록
   이 외에 부품 위치 및 자세 추정 모델 개발, 자동화 라인(로봇) 연계 가능한 파이프라인 구축, 도장 라인 등 추가 부품 분류가 필요한 라인 확장 적용.

10. 향후 추가 개발될 AI 모델의 기능은 어떤 것이 있는가?

    **답변**: **도어 6DoF 위치·자세 추정 기능(로봇 연계 대비) — 1차 구현 완료.** 홀 판별기가 검출한 홀 좌표와 CAD 홀 배치를 정합해 카메라 기준 도어의 위치·자세를 추정. 현장 데이터 280프레임에서 잔차 중앙값 3.2~4.7mm 수준이며, 실험실 레벨에서 레이저 트래커 실측(GT)을 통한 검증 예정. (과제 목표 위치 정도 3mm 이하 대비 검증 진행 중)
