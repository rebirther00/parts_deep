## 1. 데이터 종류 및 확보

1. AI 자율제조에 필요한 제조 데이터가 잘 정의되어 있는가?

   **답변**: 도어 용접 공정의 부품(도어) 종류 자동 인식을 위한 데이터로, **RGB 이미지 + Depth 이미지 쌍**을 정의하여 사용 중.
   - RGB: PNG, 1920×1200(HD1200) BGR
   - Depth: PNG uint16, mm 단위(ZED NEURAL depth)
   - 클래스: 차종 3종(E25/E30/E38) × 도어 위치(LH FRT / LH RR / RH) = **8클래스** (E30·E38 RH는 동일 부품이라 1클래스로 통합)
   - 클래스별 판별 기준을 CAD(STL)에서 추출하여 스펙화(`attribute_models/class_spec.json`: 외형 치수, 통풍구 슬롯 수, 종횡비).
   - 부수 데이터: 세션별 `meta.json`(클래스·시각·저장 쌍 수·종료 사유), 전체 버튼/세션 이벤트 로그 `events.jsonl`(라벨 정정 추적용).

2. 실라인에서 획득되는 제조 데이터 스펙(샘플링 주기, 속도, 통신방법 등)은 잘 정의되어 있는가?

   **답변**: 현장(경주 공장) 수집 장비·스펙은 `DOC_factory_collect.md`에 정의되어 운영 중.
   - 장비: ZED X mini(GMSL) + ZED Box + LTE 라우터 + 16" 터치모니터
   - 카메라: HD1200(1920×1200), NEURAL depth, mm 단위
   - 샘플링: 취득 시작 후 2초 워밍업 → **2초에 1장** rgb/depth 쌍 저장 → 작업자 종료 버튼(미조작 시 300초 후 자동 종료)
   - 통신: 현장 장비 → 세종 NAS 업로드는 **rclone**(취득 종료 시 즉시 + cron 5분 주기 보완). 원격 모니터링은 tailscale(주)/ZeroTier(백업) VPN.
   - 실험실 원본 데이터셋(`datasets`, 1,256장)은 ZED X Mini로 사무실에서 취득(웹 UI `01_capture_dataset.py`, 블러 임계값으로 흐린 프레임 자동 제외).

3. AI 자율제조를 위해 부족한 데이터 셋이 무엇인지? 확보 계획은?

   **답변**: **현장(실라인) 데이터가 부족**함.
   - 실험실 데이터는 8클래스 모두 확보(클래스당 154~161장)되었으나, 현장 데이터는 8클래스 중 **2클래스(E25_door_LH_RR 12장, E30_E38_door_RH 66장)만** 확보됨. 실험실 데이터만으로 학습한 CNN이 현장에서 붕괴(14.1%)한 것이 확인되어 현장 데이터 확보가 최우선 과제.
   - 확보 계획(진행 중): 2026-07-29부터 경주 공장에 **무인 수집 시스템(키오스크)** 설치·가동. 작업자가 도어 종류 버튼 → 취득 시작/종료만 누르면 자동 저장·NAS 업로드. 목표는 8클래스 전부, 클램프 가림 포함 다양한 조건, 클래스당 2세션 이상.
   - 라벨 검증 계획: 현장 라벨은 속성 파이프라인(CAD 기반) 예측과 교차 검증(실제로 라벨 오류 1건을 파이프라인이 검출한 사례 있음).

## 2. 데이터 전처리

1. 취득되는 제조 데이터 중 불필요 데이터를 정의하고 있는가?

   **답변**: 정의·자동 처리 중.
   - 취득 단계: 워밍업 2초 구간(노출 불안정) 저장 제외. 실험실 취득 시 블러 점수(Laplacian) 임계값 미만 프레임 제외.
   - 라벨 생성 단계: CAD 정합 IoU < 0.8(마스크 불량) 이미지는 학습에서 자동 제외.
   - 현장 촬영 프로토콜로 부적합 데이터 정의(`DOC_attribute_pipeline.md` §5): 도어가 프레임에 잘린 이미지, 한 프레임에 도어 2장, 클램프·지그 가림 과다 — 이들이 현장 클래스 정확도 저하의 직접 원인임을 확인.
   - `Unknown` 라벨 세션은 학습 미사용(수동 라벨링 전까지).

2. 제조 데이터 내 몇 종의 전처리 기법이 활용되고 있는가?

   **답변**: 두 파이프라인에서 아래 기법 사용.
   - CNN(RGBE): RGB 3채널 + Depth 기반 **Edge 채널 합성(4채널)**, 448×448 리사이즈, 정규화, 학습 시 온라인 증강.
   - 속성 파이프라인: ① MobileSAM 도어 마스크 추출 → ② Depth 평면 피팅 기반 **정면 직교뷰 렉티파이(2mm/px)** → ③ medianBlur(3) 노이즈 제거 + 소형 성분(<3cm²) 제거 → ④ PCA 축정렬 → ⑤ 종횡비 계산(절대 치수 대신 비율 사용으로 카메라 차이에 불변) → ⑥ CAD 템플릿 정합(방향 정합 후 리사이즈).
   - U-Net 학습: 온라인 광도 증강(밝기/감마/노이즈/블러).
   - 오프라인 증강셋 `datasets_aug`/`aug2`는 학습이 아닌 **강건성 평가 전용**으로 규정.

3. 저장할 제조 데이터 표준 형태가 정의되었는가?

   **답변**: 정의됨.
   ```
   <날짜>/<클래스>/s_<HHMMSS>/
     rgb_0000.png     # 1920×1200 BGR PNG
     depth_0000.png   # uint16 PNG, mm
     meta.json        # class_name, 시각, capture_interval_s, session_duration_s, saved_pairs, finished, stop_reason
   events.jsonl       # 모든 버튼/세션 이벤트
   ```
   - 실험실 데이터셋도 동일한 `rgb_XXXX.png`/`depth_XXXX.png` 쌍 규칙.
   - 메타데이터 DB 스키마(`db/schema.sql`)에 datasets/classes/capture_sessions/images 테이블로 표준화.

4. 정의되었다면, 표준 형태로의 데이터 가공을 누가 하는가?

   **답변**: **수집 프로그램이 자동 수행**(`06_factory_capture.py`). 작업자는 클래스 버튼과 시작/종료만 조작하며, 파일명·폴더 구조·meta.json·이벤트 로그·NAS 업로드는 모두 자동. 학습 PC 측 DB 등록도 스크립트(`ingest_local.py`/`ingest_nas.py`)로 수행.

5. 제조 데이터의 품질을 관리하고 있는가? (미싱 데이터, 정합성 체크 등)

   **답변**: 아래 항목을 관리 중.
   - rgb/depth **쌍 정합성**: 항상 쌍으로 저장, `saved_pairs` 수를 meta.json에 기록. DB 인제스트는 멱등(중복 등록 방지).
   - **라벨 정합성**: 속성 파이프라인 예측과 교차 검증. 실제로 2026-04 현장 데이터 55장의 라벨 오류를 검출·2차 정정(README에 이력 기록). 종료 시 클래스 선택이 Unknown으로 자동 복귀하여 라벨 오기 방지.
   - **업로드 누락**: `.uploaded` 마커 + cron 재시도, `nas_sync.log`에 성공/실패 기록.
   - **저장 무결성**: 세션 정상 종료 여부(`finished`, `stop_reason`) 기록, 미완료 세션은 업로드 대상 제외.
   - **장비 이상**: 카메라 grab 60회 연속 실패 시 자동 재연결, 디스크 여유 20GB 미만 시 화면 경고.

6. 데이터 품질 기준을 관리하고 있는가?

   **답변**: 문서화된 기준으로 관리.
   - 촬영 프로토콜(`DOC_attribute_pipeline.md` §5): 도어 전체가 프레임 안, 프레임당 도어 1장, 가림 최소화, 도어당 10프레임 이상, 라벨은 슬롯 수·치수로 재확인.
   - 학습 사용 기준: CAD 정합 IoU ≥ 0.8, 블러 임계값 통과.
   - 평가 방법론: train/val/test 70/15/15 격리, 증강셋 학습 금지, 현장은 별도 외부셋으로 평가.
   - 라벨 정정 규칙: 파일 이동 대신 DB에서 재배정하고 `notes`에 이력 기록(`db/README.md`).

## 3. 데이터 저장 및 관리

1. 제조 데이터 저장소 및 스펙은 어떠한가?

   **답변**: 3계층 온프레미스 구조.
   | 계층 | 위치 | 역할 |
   |---|---|---|
   | 현장 수집 PC | ZED Box(경주 공장), 로컬 디스크 | 1차 저장(원본 보존), 20GB 미만 시 경고 |
   | **NAS(정본)** | 세종 NAS `Guest/weld` | 세션 단위 원본 백업·공유 (rclone 자동 업로드) |
   | 학습 PC | RTX 5090 워크스테이션 | 학습용 데이터셋 + **메타데이터 DB(SQLite)** |
   - 이미지는 파일시스템에 두고 메타데이터(경로·세션·수량·학습/평가 이력)만 DB에 저장하는 하이브리드 구조.
   - NAS 사양: Synology **DS1522+, 20TB**.

2. 메타데이터는 AI 모델 개발에 충분히 자세한가?

   **답변**: DB 스키마 9개 테이블로 데이터→학습→평가 전 과정을 추적.
   - `datasets`/`classes`/`images`: 경로, 해상도, 채널, depth 단위/비트, 블러 점수, 데이터 소스(camera/augmented), split, 로컬 동기화 여부, CAD 보유 여부
   - `capture_sessions`: 카메라 종류·모드·해상도·depth 모드·취득 간격·세션 길이·저장 쌍 수·종료 사유
   - `models`/`training_sessions`/`training_metrics`: 아키텍처, 입력 채널, 사전학습, optimizer/lr/batch/epoch, 분할 수, 에폭별 loss/val, GPU, 상태
   - `evaluation_results`: 평가 유형(in_domain/cross_domain/inference_pipeline), 정확도, F1, 혼동행렬, 클래스별 결과
   - 2026-08-25부터 학습·평가 스크립트(02/03/04/12/13)가 실행 시 **자동 기록**(`db/db_log.py`).

3. 제조 데이터 관리는 주기적으로 모니터링하는가?

   **답변**:
   - 현장 수집: 세종에서 VPN(tailscale/ZeroTier)으로 현장 키오스크 화면·프리뷰·당일 통계 원격 확인, 서비스 로그(`logs/factory_YYYYMMDD.log`)·이벤트 로그·NAS 동기화 로그 확인.
   - 현장 안정성 조치 이력: 부팅 시 CUDA 미준비 대응, 시계 미동기화(1970) 대응, 서비스 자동 재시작.
   - DB 열람: `sqlite_web`으로 브라우저 조회 가능.
   - 모니터링 주기: 당분간 **1일 2회** 원격 확인.

4. 데이터 관리 정책은 확장성(데이터 확장, 제조라인 확장, 사이트 확장, 모델 확장 등)이 있는가?

   **답변**:
   - 데이터 확장: 날짜/클래스/세션 폴더 규칙과 멱등 인제스트로 신규 세션 추가 시 재스캔만으로 등록.
   - 클래스(부품) 확장: 속성 파이프라인은 신규 리비전 대응이 **STL 1개 추가 + 템플릿 재생성**으로 완료(재학습 불필요). DB `classes`에 `model_name`/`part_type` 컬럼으로 차종·부품 종류 확장 가능.
   - 사이트/라인 확장: 수집 시스템은 설치 스크립트(`deploy/install_factory.sh`) 1회 실행으로 배포 가능, NAS 경로가 세션 트리 구조라 사이트 추가 가능.
   - 모델 확장: `models`/`training_sessions` 테이블이 아키텍처·데이터셋 무관하게 설계됨(현재 ResNet18 CNN과 U-Net 두 계열 기록 중).
   - 단계별 계획(`report/DBMS_SCHEMA_DESIGN.md`): 1단계 SQLite 구축(완료) → 2단계 현장 서버 DB 연동 → 3단계 학습·평가 로깅(완료) → 4단계 PostgreSQL 전환·다중 사용자.
   - 사이트/라인 식별은 현재 NAS 경로(세션 트리) 기반이며, 전용 컬럼 추가는 4단계(PostgreSQL 전환) 시 반영 예정.

## 4. AI 모델

1. 본 사업을 위해 고려한 국내외 AI 레퍼런스 모델이 무엇인가?

   **답변**: 실제 사용·비교한 모델은 다음과 같음.
   - **ResNet18**(ImageNet 사전학습, torchvision) — RGB / RGB-D / RGB+Edge 입력 변형 및 aux branch 유무 비교 후 **RGBE NoAux 448** 채택
   - **MobileSAM** — 도어 영역 마스크 추출
   - **U-Net**(소형, 32~256ch) — 통풍구 세그멘테이션
   - 검토 후 기각: Multi-CAD ICP 분류(절대 스케일 신뢰 불가로 기각, 검증 게이트/포즈 용도로만 유효)

2. AI 모델을 적용해서 기대하는 벤치마크 성능에 대한 자료가 있나? (현재 수준)

   **답변**: 현재 수준(N=10 프레임 집계, 그룹 정확도 / 클래스 정확도, %):

   | 모델 | 실험실 test | 증강 aug | 증강 aug2 | 현장(78장) |
   |---|---|---|---|---|
   | CNN RGBE NoAux 448 (단일 프레임) | 100 / 100 | – / 92.1 | – / 93.7 | – / 14.1 |
   | 속성 파이프라인 (CAD+U-Net) | 100 / 99.2~99.7 | 97.7 / 95.5 | 95.5 / 93.6 | **99~100 / 21.9** |

   - 실험실 조건에서는 두 모델 모두 사실상 100%. 현장에서는 CNN이 붕괴하고 속성 파이프라인은 그룹(FRT/RR/RH) 판별 100%.
   - 현장 클래스 ~22%의 원인은 촬영 프로토콜 위반(프레임 잘림·이중 도어·클램프 가림)으로 규명됨(알고리즘 한계 아님).
   - 결과 파일: `artifacts/rgbe_noaux_448_seed42/eval_results.json`, `attribute_models/eval_attr_*.json`, DB `evaluation_results`.
   - 과제 목표: **인식률 99% 이상, 위치 정도 3mm 이하**. 인식률은 실험실 조건에서 목표 달성(99.2~100%), 현장 조건은 데이터 재수집 후 재평가 예정. 위치 정도는 본 분류 업무 범위 밖(별도 항목).

3. 개발한 AI 모델을 적용해서 기대하는 검증 시나리오가 있는가?

   **답변**: 구현된 검증 시나리오:
   - 실험실 test 분할(격리) → 증강셋 강건성 → 현장 외부셋 3단계 평가(`03`/`04`/`13` 스크립트, 부트스트랩 2000회).
   - 실시간 추론 서버(`05`: CNN, 웹 UI :5001 / `14`: 속성 파이프라인, 웹 UI :5003)로 ZED 카메라 라이브 판정. `--replay` 모드로 카메라 없이 현장 세션을 재생하여 동일 판정 로직 검증.
   - 향후: 현장 프로토콜 준수 재취득 데이터로 세션 단위 분할 평가(프레임 분할 금지), CNN+속성 파이프라인 하이브리드(불일치 시 판정 보류).

4. 개발된 AI 모델이 동일 업종, 다른 공정에 적용/확장이 가능한가?

   **답변**: 속성 파이프라인은 **CAD(STL)에서 판별 기준을 자동 생성**하는 구조라, CAD가 있는 판금 부품이면 슬롯/치수 기반 판별을 다른 부품·공정에 적용 가능하며 신규 부품 추가가 STL 추가로 끝남. CNN 파이프라인은 폴더 단위 라벨 데이터만 있으면 재학습으로 임의 부품 분류에 적용 가능. 수집 시스템(키오스크+NAS+DB)은 부품 종류와 무관하게 재사용 가능.
   - 타 공정 실제 적용 사례는 아직 없음(가능성 수준).

5. AI 모델 개발에 활용된 알고리즘 등은 무엇이고 성능은 어느정도인가?

   **답변**:
   - **A. CNN 분류**: ResNet18(ImageNet 사전학습) 백본, 입력 RGB+Edge 4채널 448×448, aux branch 제거(NoAux), Adam lr 0.001, batch 64, 최대 60 epoch, early stop, CrossEntropy(클래스 가중치). 실험실 test 100% / 증강 92~94% / 현장 14.1%.
   - **B. 속성 파이프라인**: MobileSAM 마스크 → depth 평면 렉티파이 → U-Net 통풍구 세그멘테이션(BCE+Dice, 라벨은 CAD 자동 생성) → CAD 템플릿 매칭(그룹) × PCA 종횡비(차종) 결합 점수 → N=10 프레임 다수결/중앙값. 실험실 test 그룹 100% / 클래스 99.2~99.7%, 현장 그룹 100%.
   - 추론 속도(속성 파이프라인, RTX 5090): 프레임당 약 170ms(서브샘플링 최적화 후, 269ms→170ms, 정확도 불변). 병목은 SAM(20ms)이 아닌 CPU 기하 단계.

6. AI 모델의 지속적인 개선을 위한 프로세스는 마련되어 있는가?

   **답변**: 마련됨.
   - 재현 파이프라인 스크립트화: `10→11→12→13`(속성), `02→03→04`(CNN). 시드·분할 파일 고정으로 재현성 확보, run별 폴더 보관 + 배포 포인터(`vent_unet.pth`) 자동 갱신.
   - 학습·평가 이력이 DB에 자동 기록되어 모델 간 성능 비교 쿼리 가능.
   - 신규 데이터 유입 경로(현장 수집→NAS→DB) 상시 가동.
   - 문서화: 원리·검증 수치·개발 중 함정 5가지·촬영 프로토콜·리비전 추가 절차(`DOC_attribute_pipeline.md`).

7. AI 모델을 활용하여 기존 기술 대비 개선한 점은 무엇인가?

   **답변**: (기존 Vision/AI 기술 대비)
   - 일반 Vision(규칙 기반 슬롯 카운팅·에지 검출)은 조명·반사·depth 스무딩으로 프레임별 편차가 커 4가지 접근 모두 불안정했음 → CAD 정합 라벨로 학습한 U-Net 세그멘테이션으로 대체하여 그룹 판별 안정화.
   - 일반 CNN(이미지 분류)은 실물 개체를 암기하여 현장에서 붕괴(14.1%) → CAD 설계 속성(치수·슬롯 배치) 기반 판별로 현장 강건성 확보.
   - 순수 CNN 대비 속성 파이프라인은 **현장 그룹 판별 49.9% → 100%**로 개선(실험실 성능은 유지).
   - **수작업 라벨링 0장**: 통풍구 픽셀 라벨 1,256장을 CAD 정합으로 자동 생성.
   - **신규 부품/리비전 대응이 재학습 없이 STL 추가**로 완료.
   - 카메라 교체(ZED X mini ↔ ZED 2i)에도 종횡비 설계로 판정 불변 확인.
   - 파이프라인이 사람의 라벨 오류를 검출한 사례 확보.

8. AI 모델의 제조 현장 적용을 통해 얻은 성과는 무엇인가?

   **답변**: 현재까지는 **현장 데이터 수집 시스템 적용 단계**이며, 모델의 현장 상시 적용(판정 결과의 공정 활용)은 아직 수행하지 않았음. 현장 관련 확인된 성과:
   - 경주 공장 용접 라인에 무인 수집 시스템 설치·가동(2026-07-29~), 작업자 설명서 배포.
   - 현장 데이터로 실험실 모델의 한계(도메인 갭)를 정량 확인하고 대안(속성 파이프라인)을 검증.
   - 현장 데이터 라벨 오류를 모델이 검출·정정.

9. 지속적인 AI 모델의 성능 개선을 위한 계획이 있는가?

   **답변**: 채택된 방향(2026-07-14 결정):
   - 현장 8클래스 재수집 완료 후 **CNN(RGBE NoAux)을 실험실+현장 혼합 데이터로 fine-tune**, 세션 단위 분할로 평가.
   - 속성 파이프라인은 폐기하지 않고 **불일치 시 판정 보류 게이트**로 유지(하이브리드).
   - 현장 데이터 축적 시 종횡비 기준값(aspect_center) 재캘리브레이션.
   - 촬영 프로토콜 준수 여부를 현장에서 재점검.

10. 향후 추가 개발될 AI 모델의 기능은 어떤 것이 있는가?

   **답변**: 계획된 기능:
   - 실시간 서버에 CNN+속성 파이프라인 하이브리드 통합(불일치 시 보류).
   - 엣지 장비(Jetson 계열 ZED Box)에서의 추론 최적화(현재 서브샘플링·SAM 재사용·FP16 옵션 구현, Jetson 실측은 1초/프레임 → 최적화 효과 재측정 예정).
   - 현장 수집 서버의 DB 직접 연동(DBMS 2단계).

## 5. AI 인프라

1. AI/MLOps 체계 등 SW 인프라는 어느 정도 구축되어 있는가?

   **답변**: 구축된 항목:
   - 데이터 수집: Flask 키오스크 서비스 + systemd 자동 시작/재시작 + rclone NAS 자동 업로드
   - 데이터 관리: SQLite 메타데이터 DB(9 테이블), 로컬/NAS 인제스트 스크립트, 웹 열람(sqlite_web)
   - 학습/평가: 스크립트화된 재현 파이프라인, 시드·분할 고정, run별 산출물 보관, 학습·평가 결과 DB 자동 로깅
   - 추론: 웹 UI 실시간 추론 서버 2종, 리플레이 검증 모드
   - 형상 관리: git(모델 가중치·이미지는 미추적, 재생성 가능)
   - 미구축: 실험 추적 도구(MLflow 등), 자동 재학습 트리거, 모델 레지스트리(현재는 폴더+DB 기록).

2. 엣지컴퓨팅 구축 계획은 어떻게 되는가?

   **답변**: 현장 ZED Box(NVIDIA Jetson Orin NX 16GB)를 수집 장비로 이미 운용 중이며, 같은 장비에서 속성 파이프라인 추론을 실측(1초/프레임)하고 최적화 옵션(서브샘플링, `--sam_every`, `--fp16`)을 구현함. 최종 추론을 엣지(ZED Box)에서 수행할지 학습 PC/서버에서 수행할지는 최적화 실측 결과에 따라 결정 예정.
   - ZED Box 사양: **NVIDIA Jetson Orin NX 16GB**.

3. GPU 인프라 구축 계획/활용 계획은 어떻게 되는가?

   **답변**: 학습 PC로 **NVIDIA RTX 5090(32GB) 워크스테이션**(Intel Core Ultra 9 285K, RAM 62GB) 운용 중. CNN 학습, U-Net 학습(약 10분), 평가, 실시간 추론 서버, DB 호스팅을 이 장비에서 수행. 현장 엣지 GPU는 ZED Box(Jetson).

4. AI 인프라의 최종 운영 환경이 어떻게 되는가? (온프레미스, 클라우드)

   **답변**: **온프레미스**. 현장 엣지(ZED Box) — 세종 NAS(정본) — 세종 학습 PC(GPU·DB) 구성이며, 사이트 간 연결은 VPN(tailscale/ZeroTier). 클라우드 사용 계획 없음.
   - 추론 서버 위치: 현재는 **세종 사무소**(학습 PC)에서 운영.
