## 2. 데이터 전처리

1. 홀 판별기 입력 전처리는?

   **답변**: 원본 RGB(1920×1200/1080)를 **1280×768 letterbox**(비율 유지, 회색 패딩) → ImageNet mean/std 정규화. Depth는 CNN에 넣지 않고 검출 후 거리 계산에만 사용. 도어 영역 분리(SAM)·정면 뷰 변환 없이 원본 프레임을 그대로 사용하므로 속성 파이프라인보다 전처리가 단순함.

2. 학습 시 증강은?

   **답변**: 도어가 지그에 임의 각도로 놓이므로 **회전 불변**이 핵심. 학습 샘플마다 임의 아핀 — 회전 ±180°, 스케일 0.75~1.15, 이동 ±60px, 50% 좌우 플립, 밝기·대비(0.7~1.3, ±30), 30% 블러. 에폭당 원본 4회 재샘플. (오프라인 증강셋 `datasets_aug`는 이 모델 학습에 미사용)

3. 불필요·부적합 데이터는 어떻게 걸러지는가?

   **답변**: 판정 단계의 **기하 게이트**가 프레임 단위로 판정 가능 여부를 결정하고, 불가하면 "보류"(오판과 구분).
   - `no_corner` 모서리 홀 미검출 / `near_border` 홀이 이미지 경계 20px 이내 / `no_frame` 볼트홀 4개가 157×96mm 직사각형 불일치 / `latch_offset` 래치측 홀 위치 불일치 / `not_collinear` 두 홀이 같은 선상 아님 / `same_side` 두 홀이 볼트 사각형 같은 쪽 / `D_range` 600~1500mm 밖
   - 현장 빈 지그 9장이 전부 `no_frame`/`no_corner`로 보류된 것이 정상 동작 사례. 실험실 보류 ~30%는 도어를 꽉 채워 찍은 사무실 프레이밍(힌지측 홀이 프레임 밖) 때문이며 현장은 0%.

## 4. AI 모델

1. 홀 랜드마크 판별기는 무엇이며 왜 도입했는가?

   **답변**: 도어 8종은 형상이 거의 같고 치수(폭 830~1,458mm)만 다르다. 형상을 학습하는 CNN 분류기(ResNet18 RGB+Edge)는 실험실 100%였으나 현장 개체에서 **14.1%**로 붕괴(클래스당 실물 1개의 외관을 지문처럼 암기). 이에 **AI는 "홀 위치 검출"만 하고, 판정은 설명 가능한 CAD 치수 비교**로 하는 방식으로 전환.
   - 원리: 8종 모두 좌우 세로 프레임 끝에 동일 위치의 Ø6mm 홀 한 쌍(가장자리 52~54mm, 변에서 105mm) → 두 홀 거리 **D = 도어 폭 − 106mm**. 8종의 폭이 모두 달라 D만으로 구분(최소 간격 FRT 3종 41~47mm, 나머지 50~200mm).
   - CAD D vs 사람 라벨 실측 D: 8종 모두 ±7mm 이내(홀만 정확히 찾으면 GT 기준 최근접 분류 87/87 = 100%).
   - 중앙 보강대 패드 홀은 옵션/리비전에 따라 패턴이 달라 사용 금지.

2. 모델 구조(입력·출력·레이어)는?

   **답변**: **ResNet18 인코더 + FPN식 디코더 + 히트맵 헤드** (`hole_classifier.Net`).
   - 입력 `[3, 768, 1280]` / 출력 히트맵 `[3, 192, 320]`(stride 4) — 채널: bolt(4 피크) / corner_hinge / corner_latch
   - 인코더: torchvision ResNet18(ImageNet 사전학습)에서 avgpool/fc(분류용 꼬리)를 제거. c1 64ch 1/4 → c2 128ch 1/8 → c3 256ch 1/16 → c4 512ch 1/32
   - 디코더: 각 단계를 1×1 conv로 128ch로 맞추고 bilinear 업샘플 + 덧셈으로 1/4까지 복원(깊은 층의 문맥 + 얕은 층의 위치 정밀도)
   - 헤드: conv3×3(128→128)+BN+ReLU → conv3×3(128→64)+BN+ReLU → conv1×1(64→3)
   - 후처리: 11×11 NMS + 임계 0.15 → 포물선 서브픽셀 보정 → letterbox 역변환 → 원본 픽셀 좌표
   - 파라미터 약 11.6M, RTX 5090에서 홀 단계 **41ms/프레임**

3. 왜 거리 계산에 쓰는 모서리 홀 2개 외에 볼트홀 4개까지 검출하는가?

   **답변**: 볼트홀 4개(래치 각공 주변 157×96mm 직사각형)는 **답을 검증하는 자** 역할.
   - 기준 좌표계: 볼트 사각형으로 도어 좌표계(중심·축·px/mm)를 만들어 모서리 홀 2개의 위치·공선성·반대편 여부를 검사(기하 게이트) → 녹·그림자·하단 홀·패드 홀 오검출을 차단. 오판 중 "엉뚱한 홀을 잡은" 건은 0건
   - 방향 결정: 볼트 뭉치가 있는 쪽 = 래치측 → 도어가 어떤 방향으로 놓여도 힌지/래치 구분
   - 예비 스케일: Depth 불량 시 볼트 간격(실제 mm 기지)으로 px/mm 환산해 D 계산(`D_src='bolt'`)

4. 학습 기법(타깃·손실·최적화)은?

   **답변**:
   - 타깃: stride-4 격자에 σ=2 가우시안 히트맵. 좌표 회귀보다 다중 피크·안정 수렴에 유리
   - 손실: 가중 MSE(양성 픽셀 ×21). 히트맵이 대부분 0이라 단순 MSE는 전부 0으로 붕괴
   - 최적화(채택): AdamW lr 1e-4, weight decay 1e-4, 3 epoch 워밍업 + 코사인 감쇠, gradient clip 1.0, FP32, 80 epoch. 30 epoch부터 홀드아웃 ≤8px 100%
   - 폐기한 시도: ① OneCycle max_lr 3e-4 + FP16 → 20 epoch 후 발산 ② 규칙 기반 검출(블랙햇 모폴로지·NCC 템플릿) 3차례 → 사람 라벨(GT) 대비 볼트홀 오검출 53%, 모서리 홀 60%, 방향 판정 48%로 폐기. 교훈: 검출 정확도는 반드시 GT로 측정

5. 판정 파이프라인과 정책은?

   **답변**: CNN 6점 검출 → Depth로 도어 평면 피팅, 두 모서리 홀을 평면에 투영해 mm 거리 D(카메라 모드별 스케일 상수 K_DEPTH 1080p 0.8235 / 1200p 0.8505 보정) → 기하 게이트 → CAD D 표 최근접 → 실시간은 10프레임 윈도의 판정 프레임 D 중앙값 집계.
   - 하이브리드: 홀 D의 최근접 마진 ≥30mm → 홀 판정 우선 / 15~30mm → 속성 파이프라인(통풍구 U-Net) 그룹 내 최근접 / <15mm → 보류. 판정 프레임 3개 미만이면 속성 파이프라인 폴백
   - 실시간 서버(`14_realtime_inference_attribute.py`, :5003) 통합 완료. API `/api/inference_result`에 `source`(hole/attr/conflict)·`hole{pred, D_mm, n_judged, gate, margin_mm, points}`

   **답변** (라벨 학습분 107장 제외):

   | 평가 세트 | 전체 | 판정 | 정답 | 판정 정확도 | 그룹 정확도 |

   | 실험실 전체 | 1,162 | 814 (70%) | 806 | **99.0%** | 99.5% (그룹 제약 시 정확도 99.5%) |
   | 현장 E25_door_RH (08-10) | 16 | 16 | 16 | **100%** | 100% |
   | 현장 E30_door_LH_RR (08-27) | 29 | 29 | 29 | **100%** | 100% |
   | 현장 E30_door_LH_FRT (08-27) | 149 | 149 | 149 | **100%** | 100% |
   | 현장 빈 지그 (08-27) | 9 | 0 | — | 전부 보류(오판 0) | — |

   - 홀 검출 정확도(GT 대비): 홀드아웃 27장 6점 중앙값 1.0~1.4px, 4px 이내 100%, 오검출(>20px) 0%. 현장 16장 0.7~1.4px. 1px ≈ 1.3mm → D 오차 ±2~3mm

   - 증강셋(`datasets_aug`) 평가는 미수행(기하 판정이라 색상·블러 영향이 작고 회전 증강으로 학습)

7. 검증 시나리오는 기존 모델과 같은 조건인가?

   **답변**: 같은 분할 파일(`split.json` seed42)·같은 평가 스크립트 체계. 실험실 시험셋(격리) → 실험실 전체 → 현장 외부셋(학습 미사용, 단 E25_RH 16장은 라벨에 사용했으므로 판정 평가에서 제외하고 검출 정확도만 별도 산출). 2026-08-27 현장 189장은 학습·라벨 어디에도 쓰지 않은 완전한 외부셋.

8. 기존 기술 대비 개선점은?

   **답변**:
   - 규칙 기반 홀 검출(모폴로지·템플릿) 대비: GT 기준 오검출 48~60% → 0%
   - 형상 학습 CNN 분류 대비: 현장 14.1% → 100%(3종), 판정 근거가 "실측 D 1157mm ↔ CAD 1158mm"처럼 숫자로 제시되어 설명 가능
   - 라벨 비용: 픽셀 라벨 134장·1시간(속성 파이프라인 통풍구 라벨은 0장). 신규 클래스 추가 시 재학습 불필요

9. 타 공정·신규 부품 적용 가능성은?

   **답변**: 신규 차종/리비전은 **CAD에서 D 값 1개를 `hole_classifier.CAD_D`에 추가**하면 판정 대상에 포함(픽셀 라벨링·재학습 불필요). 단 실물 수십 프레임으로 기준값 1회 보정 절차를 둠. 새 카메라·해상도 모드는 라벨 10장으로 K_DEPTH 캘리브레이션. 한계: 기존 클래스와 D 차이 ~40mm 이내면 구분 불가, 신규 클래스 추가 실증은 미수행. 동일 위치 홀 쌍이 있는 판금 부품이면 같은 방식 적용 가능.

10. 현장 적용 성과와 성능 개선 계획은?

    **답변**: 현재는 수집 단계이며 판정은 세종 학습 PC에서 오프라인(현장 세션 리플레이). 2026-08-27 설치 당일 수집분 178장 판정 178 정답.
    - 계획(우선순위): ① 현장 5종 수집·8종 검증 ② ZED SDK 정식 intrinsics로 거리 정밀화(측정 오차 p95 20mm→10mm, FRT 간 오판 제거) ③ Jetson(ZED Box) TensorRT/FP16 배포 → 취득 세션마다 자동 판정·DB 기록 ④ 현장 데이터로 U-Net 그룹 판별 재점검(현장 E25_RH에서 U-Net이 RR로 오판한 이력) 및 마진 임계 조정 ⑤ 촬영 프로토콜(힌지측 프레임 상단이 반드시 화면 안)

11. 알려진 제약은?

    **답변**: 힌지측 홀이 프레임 밖이면 판정 불가(촬영 프로토콜로 해결, 그 경우 속성 파이프라인이 그룹만 제공) / K_DEPTH는 카메라 모드별 상수 / 현장 검증은 3종에 한정, 나머지 5종은 실험실 결과로부터의 추정 / 거리 측정 오차 20~58mm 구간에서 인접 클래스 오판 가능.

## 5. AI 인프라

1. 현장 엣지 장비에서 무엇이 돌아가고 있는가?

   **답변**: ZED Box(Jetson Orin NX 16GB)에서 수집 서비스(`06_factory_capture.py`, Flask :5000, systemd `door-capture.service` 부팅 자동시작·5초 재시작) + 키오스크 웹뷰(`deploy/kiosk.sh`, WebKit2GTK, 자동 로그인 시 전체화면, Alt+F4 시 3초 후 재실행) + NAS 동기화(`deploy/nas_sync.sh`, cron 5분). 설치는 `deploy/install_factory.sh` 1회 실행. 추론은 아직 미배포(세종 PC에서 오프라인).

2. 엣지 추론 계획은?

   **답변**: 홀 검출기(ResNet18-FPN, 1280×768)를 TensorRT/FP16으로 변환해 ZED Box에서 속도 실측(5090 41ms 기준) 후, 수집 서비스와 연동해 취득 세션 종료 시 자동 판정 → 결과를 `meta.json`·DB에 기록. 최종 추론 위치(엣지 vs 세종 서버)는 실측 결과로 결정.

3. 원격 운영·모니터링은?

   **답변**: 세종에서 tailscale(`http://100.70.228.127:5000`)/ZeroTier(예비)로 현장과 같은 화면·프리뷰·당일 통계·로그 확인, SSH로 `journalctl -u door-capture`·`events.jsonl` 확인. 1일 2회 점검. 양 경로 불통 시 현장에 전화해 전원 재투입 요청(트러블슈팅 표 `DOC_factory_collect.md`).

| 현장 장비가 꺼지면? | 전원 재투입만으로 2~3분 내 자동 복구(서비스·키오스크·시계·GPU 대기 모두 자동). 원격 불통 시 현장 전화 |
