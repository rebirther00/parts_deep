## 1.1 데이터 수집

### Q1. 데이터 명세서와 실제 수집·활용 데이터가 다른 이유
**우리 상황의 유사 질문**: "계획서에는 8종 도어 현장 데이터 수집인데 실제 확보는 2종뿐인 이유는?" / "증강 데이터 2,512장은 왜 학습에 안 쓰는가?"

**예시 답변**
- 실험실 데이터는 계획대로 8종 전부(1,256장) 확보했고, 현장 데이터는 현장 생산 순서에 따라 취득 가능한 도어가 결정되어 현재 2종(E25 LH RR, E30/E38 RH)만 확보된 상태입니다. 2026-07-29부터 무인 수집 시스템을 상설 가동하여 생산되는 순서대로 나머지 종류를 축적 중입니다.
- 증강 데이터(1차·2차 각 1,256장)는 "학습용"이 아니라 **강건성 평가 전용**으로 용도를 확정했습니다. 증강 데이터를 학습에 넣으면 평가 벤치마크가 오염되고, 실제로 극단 증강 강건성이 현장 성능을 전혀 예측하지 못한다는 것(증강 92~94% vs 현장 14%)을 확인했기 때문입니다. 대신 학습 시 온라인 광도 증강만 사용합니다.
- 현장 1차 데이터(2026-04) 중 55장은 라벨 오류가 있어 2회에 걸쳐 정정했고, 이력을 README와 DB에 기록했습니다. 명세서 수량과 차이가 나는 부분은 이 정정과 잘못 수집분 제거 반영분입니다.

### Q2. 공정 데이터 수집주기 및 부족 데이터 확보계획
**예시 답변**
- 수집 주기: 현장 무인 수집 시스템이 취득 시작 후 2초 워밍업 → **2초당 1장** RGB/Depth 쌍을 저장하며, 작업자의 종료 버튼(미조작 시 5분 후 자동 종료)까지 지속합니다. 도어 1개당 약 10프레임 이상 확보가 판정 단위입니다.
- 부족 데이터: 현장 8종 중 6종. 확보 계획은 ① 무인 수집 시스템 계속 가동(작업자는 도어 종류 버튼 + 시작/종료만 조작), ② 세종에서 1일 2회 원격 모니터링, ③ 라벨은 CAD 기반 AI 판정과 교차 검증, ④ 종당 2세션 이상·클램프 가림 등 다양한 조건 확보 후 실험실+현장 혼합 재학습.
- 2026-08-25 기준 NAS 누적 5세션 77쌍이며, 이 중 61장이 "Unknown"(작업자가 종류 미선택)이라 수동 라벨링 예정입니다.

### Q4. 표면결함 이미지 확보 및 라벨링 현황
**[해당 없음 — 결함 검출은 본 업무 범위 아님]**

**예시 답변**
- 분류 라벨(도어 종류): 촬영 시 폴더 단위로 부여. 실험실 1,256장·현장 155장 완료. 현장은 작업자가 키오스크 버튼으로 종류를 선택하며, 종료 시 자동으로 "모름"으로 초기화되어 라벨 오기를 방지합니다.
- 통풍구 픽셀 라벨 1,256장: **수작업 0장**. CAD 투영을 이미지에 정합해 자동 생성(정합 품질 IoU<0.8은 자동 제외).
- 홀 랜드마크 라벨(2026-08 신규): 자체 제작한 브라우저 라벨링 도구로 이미지당 6점(볼트홀 4 + 모서리 홀 2)을 **134장** 수작업 라벨링(8종×15장 + 현장 16장). 이 소량 라벨로 학습한 검출기가 실험실 test 100%, 전체 99.0%, 현장 16/16을 기록했습니다.
- 라벨 검증: 현장 55장 라벨 오류를 AI 판정이 검출해 정정한 사례가 있습니다.

### Q5. 학습 데이터 표준 구조 관리 및 공정 간 추적
**예시 답변**
- 표준 구조: `날짜/도어종류/세션/rgb_0000.png + depth_0000.png + meta.json`, 전체 이벤트 로그 `events.jsonl`. 실험실·현장 동일 규칙.
- 관리: SQLite 메타데이터 DB 9개 테이블(데이터셋·종류·이미지·촬영 세션·모델·학습 세션·에폭별 지표·평가 결과·증강 설정). 학습·평가 스크립트 실행 시 자동 기록되어 "어떤 데이터로 어떤 모델을 학습해 어떤 성능이 나왔는지"를 쿼리로 추적합니다.
- 추적성: 이미지 → 촬영 세션(카메라·시각·종료 사유) → 데이터셋 → 학습 세션 → 평가 결과가 외래키로 연결됩니다. 라벨 정정은 파일 이동이 아니라 DB 재배정 + 이력 기록으로 처리합니다.
- **[해당 없음]** 소재 단위 공정 간 결함 위치 추적은 본 업무 범위 아님. 도어 개체 단위 추적(어느 도어가 어느 세션에서 촬영됐는지)은 세션 단위로 가능하나, 개체 ID(시리얼)와의 연결은 현재 없음.

## 1.3 AI 모델

### Q10. 모델 개발 범위와 고도화 방향
**예시 답변**
- 범위: 도어 8종 자동 인식. 3계열 개발 완료.
  1. **CNN 분류**(ResNet18, RGB+Edge 4채널) — 실험실 100%, 현장 14%(개체 암기로 붕괴)
  2. **CAD 속성 파이프라인**(MobileSAM + 통풍구 U-Net + 종횡비) — 실험실 99.2~99.7%, 현장 그룹 100%
  3. **홀 랜드마크 판별기**(2026-08, 현재 1순위) — CNN이 홀 6점 검출 → 모서리 홀 간 거리(도어 폭−106mm)를 CAD 값과 대조. test 100%, 전체 99.0%, 현장 16/16. 기하 게이트로 불확실하면 판정 보류.
- 판정 정책: 홀 판별기 1순위, 속성 파이프라인이 그룹 제약·폴백, 불일치 시 보류(conflict 표시). 실시간 서버(:5003)에 통합 완료.
- 고도화 방향: 현장 8종 재수집 후 혼합 재학습, N프레임 집계로 FRT 계열(41mm 간격) 마진 확대, 엣지 추론 최적화, 현장 서버 DB 직접 연동.

### Q11. 벤치마크 논문과 실공정 모델을 동일 조건에서 비교했는지
**우리 상황의 유사 질문**: "실험실 100%와 현장 수치는 같은 조건인가? 비교 기준이 공정한가?"

**예시 답변**
- 모든 모델을 **동일한 데이터 분할·동일한 평가 스크립트**로 비교합니다: 실험실 시험셋은 학습에서 완전 격리된 15%(분할 파일 고정), 증강셋은 전체, 현장은 학습 미사용 외부셋. 부트스트랩 2,000회로 N=10 프레임 집계 정확도를 산출합니다.
- 실험실 수치와 현장 수치는 **의도적으로 다른 조건**(도메인 갭 측정 목적)이며, 이를 같은 조건으로 오해하지 않도록 표에서 항상 분리 표기합니다.
- 논문(JKSPE 투고용)에서는 5-seed 반복 실험, pairwise paired t-test로 입력 변형(RGB/RGB-D/RGB+Edge) 간 차이를 검정했습니다.
- 주의: 라벨 정정 이전 산출된 현장 수치는 무효 처리하고 인용하지 않습니다.

### Q14. 모델 검증·이관, MLOps 구축 및 교육
**예시 답변**
- 검증: 3단계(실험실 격리 시험셋 → 증강 강건성 → 현장 외부셋) + 실시간 서버 재생 모드로 현장 세션 재검증. 결과는 DB에 자동 기록.
- 이관: 모델 가중치는 run별 폴더 보관 + 배포 포인터 자동 갱신. 현장 배포는 설치 스크립트 1회 실행(systemd·키오스크 자동 구성). 추론 서버는 웹 UI/REST API(`/api/inference_result`에 판정 소스·거리·게이트 포함) 형태라 타 시스템 연동 가능.
- MLOps 현황: 재현 가능한 학습·평가 파이프라인(시드·분할 고정), 학습·평가 결과 DB 자동 로깅, 데이터 자동 유입(현장→NAS→DB)은 구축. 실험 추적 도구·자동 재학습·모델 레지스트리는 미구축(향후).
- 교육: 현장 작업자 대상 키오스크 사용 설명서(docx) 배포·게시 및 설치일 시연·직접 수행 완료. 개발자용 운영 문서(재시작·로그·트러블슈팅) 작성.

## 1.4 기타

### Q15. 데이터 외부 제공 절차 및 품질관리 조직
**예시 답변 (사실 범위)**
- 데이터 정본은 세종 NAS(`Guest/weld`)에 세션 단위로 보관되며, 학습 PC DB로 "무엇이 어디에 얼마나 있는지" 즉시 조회 가능해 제공 요청 시 목록·수량 산출이 가능합니다.
- 품질관리: 촬영 프로토콜·학습 사용 기준·평가 방법론·라벨 정정 규칙을 문서화하고, DB에 정정 이력을 남깁니다.
- **[확인 필요]** 외부 제공 승인 절차와 품질관리 조직(담당자·위원회)은 기관 차원 사항이라 답변 전 확인 요망.

### Q16. 참여기관 간 기존 협업 경험
**[확인 필요 — 기관 차원 사항]** 기술적으로 확인 가능한 사실: 현장(경주 공장)에 수집 장비를 설치·운영하고 작업자가 일일 수집에 참여하고 있으며, 세종–현장 간 원격 운영 체계가 가동 중임.
