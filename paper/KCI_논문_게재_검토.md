## 2. 논문 게재 가능성 판단: **게재 가능 (보완 필요)**

### 2.1 강점 — 논문 기여 가능 요소

#### (1) RGBE 하이브리드 입력 표현 [기여도: 높음]
- RGB + Canny Edge 4채널 입력이 RGBD 대비 텍스처 변형 강건성 2.7배 향상
- 하락폭 기준: RGBD -13.79%p → RGBE -5.18%p
- 동일 아키텍처(Aux-ResNet18)에서 입력 채널만 변경한 **통제된 ablation** 설계

#### (2) 체계적 4종 모델 비교 실험 [기여도: 높음]
- Baseline RGBD / Texture Aug RGBD / Edge-only / RGBE Hybrid
- 3개 평가 데이터셋(원본, 전경만 증강, 전체 증강)에서 교차 평가
- 2개 해상도(224, 448)에서 반복 — 총 24개 실험 조건
- 동일 백본·동일 Aux·동일 하이퍼파라미터로 **입력 표현의 순수 효과**를 분리

#### (3) Depth 기반 물리 치수 보조 피처 [기여도: 중간]
- SAM 마스크 + Depth 맵 → 3D 포인트 클라우드 → PCA 주축 분해
- 물리적 폭(mm), 높이(mm), 종횡비를 산출하여 MLP로 Late Fusion
- 유사 형상 도어 간의 **크기 차이**(최소 41mm, 약 5%)를 포착하는 보완적 역할

#### (4) CAD→실물 도메인 적응 파이프라인 [기여도: 중간]
- Isaac Sim + Omni Replicator 기반 합성 RGBD 데이터 생성
- Domain Randomization: 배경(없음 20%/단색 30%/팩토리 50%), 카메라 위치/각도, 조명
- CAD 사전학습 → 실물 Fine-tuning 전략 수립 및 검증

#### (5) 해상도-강건성 상반 관계 발견 [기여도: 중간]
- 대다수 모델에서 224 해상도가 증강 데이터 강건성 향상 (암묵적 정규화 효과)
- RGBE만 예외적으로 448에서 현저히 우수 (고해상도 Edge 정보 의존)
- 입력 표현에 따른 **최적 해상도가 다르다**는 실용적 발견

#### (6) 산업 현장 적용 시스템 구현 [기여도: 보조]
- ZED X Mini + Jetson Orin 기반 실시간 추론 파이프라인
- Flask 웹 UI를 통한 데이터 수집·큐레이션·모니터링
- ONNX 변환 및 엣지 배포 (CPU 86ms/장)

### 2.2 약점 — 보완 필요 사항

#### (1) 선행 연구 조사 및 비교 부재 [심각도: 높음]

**현재 상태**: 기존 문헌과의 성능/방법론 비교가 전혀 없음

**보완 방안**:
- 산업 부품 인식 관련 선행 연구 최소 15~20편 조사
- 주요 비교 대상 분야:
  - 멀티모달(RGB-D) 입력 기반 분류: Eitel et al. (2015), Loghmani et al. (2019)
  - Edge/Contour 기반 인식: Xie & Tu (HED, 2015), 산업 부품 Edge 분류 연구
  - Sim-to-Real 전이: Tobin et al. (2017), Tremblay et al. (2018)
  - 유사 도메인: 산업 부품 분류, 자동차 부품 인식, 결함 검출 등
- 가능하면 동일 또는 유사 데이터셋에서 비교 실험 수행

#### (2) 통계적 신뢰도 부족 [심각도: 높음]

**현재 상태**: 단일 랜덤 시드(42), 표준편차/신뢰구간 미보고

**보완 방안**:
- 최소 3~5회 반복 실험 (랜덤 시드: 42, 123, 456, 789, 1024 등)
- 평균 ± 표준편차 형식으로 모든 지표 재보고
- 모델 간 차이의 통계적 유의성 검증 (paired t-test 또는 Wilcoxon signed-rank test)

#### (3) Test 100% 정확도의 과적합 의심 [심각도: 중간]

**현재 상태**: Baseline RGBD, RGBE 모두 Test 분할에서 100% (377/377)

**보완 방안**:
- 5-fold Stratified Cross-Validation 수행으로 일반성 검증
- 또는 별도의 holdout 검증셋(val) 구성 (Train 60% / Val 20% / Test 20%)
- 100%가 재현되면 데이터 특성상 당연한 결과임을 논증
- 증강 데이터 평가 결과가 실질적 일반화 능력을 반영한다고 서술

#### (4) OOD(Out-of-Distribution) 데이터 미검증 [심각도: 중간]

**현재 상태**: 증강 데이터(ColorJitter, Noise, Blur)로만 강건성 평가

**보완 방안**:
- 다른 개체의 동일 모델 도어 (인스턴스 간 일반화)
- 다른 조명/카메라 각도에서 촬영한 독립 테스트셋
- 실제 공장 현장 이미지 (가능한 경우)
- 불가능한 경우, 한계점으로 명시하고 향후 연구 방향으로 제시

#### (5) 단일 백본 아키텍처 [심각도: 낮음]

**현재 상태**: 모든 모델이 ResNet18 기반

**보완 방안** (권장, 필수는 아님):
- EfficientNet-B0, MobileNetV3 등 경량 모델과의 비교 (엣지 배포 관점)
- ResNet50, ConvNeXt-Tiny 등과의 비교 (정확도 상한 확인)
- 이 비교가 없어도 "입력 표현 비교"가 본 연구의 초점임을 명확히 서술하면 충분

#### (6) 위치 추정 파트 미완성 [심각도: 낮음]

**현재 상태**: 6DoF Pose Estimation이 V1~V4까지 반복 개발 중, 최종 성능 미보고

**보완 방안**:
- 분류 논문에 집중하고, 위치 추정은 별도 논문으로 분리
- 또는 시스템 논문으로 묶어서 분류 + 위치 추정의 전체 파이프라인을 소개

| 5 | 실험 결과 | 전체 정확도, F1-Score, 클래스별 성능, 강건성 지표(하락폭), 해상도 분석 |

| 7 | 결론 | 핵심 발견 요약, 산업 적용 의의, 향후 연구 방향 |

## 5. 게재를 위한 보완 작업 체크리스트

### 5.1 필수 보완 (투고 전 반드시 수행)

- [ ] **선행 연구 조사**: 관련 분야 15~20편 이상 문헌 조사 및 비교표 작성
- [ ] **반복 실험**: 3~5개 랜덤 시드로 전체 실험 반복, 평균±표준편차 보고
- [ ] **교차 검증**: 5-fold Stratified CV로 100% 정확도의 일반성 검증
- [ ] **논문 형식 서술**: 가설 → 실험 설계 → 결과 → 고찰 구조로 재구성
- [ ] **그림/표 학술 수준 정리**: 혼동 행렬 히트맵, 학습 곡선, 아키텍처 다이어그램

### 5.2 권장 보완 (논문 품질 향상)

- [ ] **Grad-CAM 시각화**: RGBD vs RGBE 모델이 주목하는 영역 차이 분석
- [ ] **추론 속도 정량 비교**: 각 모델의 FPS/레이턴시를 Jetson Orin에서 측정
- [ ] **다른 백본 비교**: EfficientNet-B0, MobileNetV3 등 1~2종 추가 비교
- [ ] **독립 테스트셋**: 다른 개체의 도어 또는 다른 환경에서의 평가 (가능한 경우)
- [ ] **t-SNE/UMAP 특징 공간 시각화**: 입력 표현별 클래스 분리도 비교

### 5.3 논문 작성 시 주의사항

- 100% 정확도를 주요 기여로 내세우지 말 것 (과적합 의심 유발)
- **강건성(robustness) 비교**를 핵심 기여로 프레이밍
- 데이터셋 규모의 한계를 솔직히 기술하고, 소규모 데이터 전략으로 의의 부여
- 산업 현장 적용 가능성을 강조 (엣지 배포, 실시간 추론)
- RGBE의 한계도 함께 논의 (448 해상도 필수, Edge 계산 추가 비용)

## 7. 종합 판단

### 결론: **KCI 등재지 게재 가능**

현재 프로젝트는 **KCI 등재지 게재에 충분한 기술적 깊이와 실험량**을 보유하고 있다.

**주요 근거**:

1. **차별화된 기여점 존재**: RGBE 하이브리드 입력 표현 + 물리 치수 보조 피처의 조합은 기존 RGBD 연구와 차별화되며, 텍스처 변형 강건성에서 실증적 우수성을 입증
2. **체계적 실험 설계**: 4종 모델 × 3개 평가셋 × 2개 해상도 = 24개 조건의 체계적 비교는 학술적으로 충분한 실험량
3. **산업 적용 관점**: 건설기계 제조 현장이라는 구체적 응용 분야에서의 실증은 산업 분야 학술지에 적합
4. **데이터·코드 완비**: 실험 재현에 필요한 코드, 데이터, 로그가 모두 체계적으로 관리됨
