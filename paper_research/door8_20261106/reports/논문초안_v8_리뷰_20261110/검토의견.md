# 논문초안 v8 재검토 의견

검토일: 2026-11-10. 대상은 v8 HWPX·PDF와 동반 MD·DOCX, 검토답변·작성확인사항·차별성 문서, 보완된 scope 정정 기록이다. 이전 v7 검토의 네 지적이 실제 파일에 반영됐는지 확인했다. 원본 8개와 기존 실험 결과는 변경하지 않았다.

## 1. 판단

**v7에서 남긴 네 지적은 모두 해결됐다. 다만 v8 답변서에 새로 추가한 학습 세션 설명에 수치 오류 하나가 있으므로 이를 고치고, 저자·후기 정보와 최종 한글 배치를 확정한 뒤 투고를 진행할 수 있다.** 새 오류는 답변서·대응 기록의 사례 설명에 있으며, 원고의 시험 결과나 표를 바꾸는 문제는 아니다. 추가 학습·추론이나 새로운 실험은 요구하지 않는다.

논문의 주장은 현재 범위로 유지하는 것이 타당하다. 공통 홀 검출과 CAD 판정 목록의 운영상 분리, 거리 표현에 따른 실패 진단, 조건을 구분한 품종 목록 운용을 실제 생산 자료로 검증했다. 게재를 보장할 수는 없지만, 이전에 지적한 비교 조건과 해석의 문제를 해결한 상태다. 남는 심사 쟁점은 응용 기여의 충분성, 한 현장·한 시드의 범위, 소프트맥스 기준선에 한정된 비교다.

## 2. 이전 네 지적의 처리

| v7 지적 | v8에서 확인한 내용 | 판단 |
|---|---|---|
| 3.1 경계 동률 | 3.2절에서 경계를 별도 규칙에 연결하고, 3.6절에서 CAD 목록 순서의 동률 처리와 정확히 30 mm일 때 수락을 명시 | 해결 |
| 3.2 로그 해시 | JSON 14개·scope 경로 16개 확인. 로그 5개 해시는 실제 파일 및 v7 검토 당시 기록과 모두 일치. amendments에 보완 경위 기록 | 해결 |
| 3.3 시험 범위 | 5.3절과 차별성 주장 B에 ‘시험’ 명시. 질문 11에서 공통 미학습 74도어와 공통 학습·일반 식별 361도어를 구분 | 해결 |
| 3.4 표 배치 | HWPX 본문 표 8개 모두 pageBreak=NONE, 캡션 8개 keepWithNext=1. 제공 PDF에서도 Table 1~8 각각 한 단 안에 배치 | 제공 PDF에서 해결. 한글 실제 배치는 최종 확인 |

v8 답변서가 이전의 캡션 이동과 비대칭 행 유지를 ‘견해 차이’가 아닌 편집 선택으로 정리한 것도 적절하다. 동률과 U에 관한 지적을 다시 확대하거나 기존 수치의 수정을 요구할 이유는 없다.

## 3. 교정할 사항 한 가지: ‘나머지 19장 모두 812.7 mm’는 틀림

위치: `v8_검토답변.md` 2.3절, `v8_작성확인사항.md`의 ‘확인한 수치’ 첫 행.

대상은 폴드 4의 학습 세션 `20260831/E38_door_LH_FRT/s_183313`이다. 답변서는 오류 영상 `58:rgb_0140.png`를 제외한 19장이 모두 812.7 mm였다고 하지만, 해당 모델의 저장 특징과 실제 `classify_measurement()`로 확인한 결과는 아래와 같다. 축척도 폴드 4 학습 세션에서 다시 계산해 저장 값과 대조했다.

| 영상 판정 | 장수 | 근거 |
|---|---:|---|
| E38 LH FRT 정답 | 6 | 기하 검사 통과, 측정 812.7047 mm |
| E30 LH FRT 오판 | 1 | rgb_0140.png, 기하 검사 통과, 측정 764.1189 mm |
| 보류: 모서리 홀 누락 | 11 | missing_corner |
| 보류: 볼트 배열 검사 실패 | 2 | invalid_bolt_rectangle |
| 합계 | 20 | 정답 6 / 오판 1 / 보류 13 |

따라서 오류 영상 외의 19장은 **정답 6장과 보류 13장**이다. 보류는 최빈값 투표에서 제외되므로 정답 6표가 오판 1표보다 많아 도어 판정은 정답이다. 원고에서 이미 밝힌 ‘학습 쪽 판정 여유 밖 영상 1건’, 학습 도어 실패 0, 시험 결과는 그대로 성립한다. 보류된 영상의 원시 거리 값이 있더라도 기하 검사를 통과한 측정으로 세면 안 된다.

권장 대체 문장:

> 이 학습 세션의 20장 중 6장은 812.7 mm로 측정되어 정답, 1장은 764.1 mm로 측정되어 오판, 13장은 모서리 홀 누락(11장) 또는 볼트 배열 검사 실패(2장)로 보류되었다. 보류를 제외한 최빈값에 따라 도어 판정은 정답이었다. 오판 영상의 힌지 모서리 피크 응답은 0.1554로 검출 임계값 0.15 바로 위였다.

피크 응답 0.1554 자체는 저장 값과 일치한다. 정상 판정 6장의 힌지 검출 좌표는 (1366.25, 1025.0), 오판 영상은 (1322.5, 975.0)으로 달라져 있다. 이는 약한 피크의 위치 오류라는 해석을 뒷받침하지만, 새 수동 정답 좌표로 원인을 독립 검증한 것은 아니다. 차별성 문서의 “검출 오류로 보이며”라는 제한적 표현은 유지할 수 있다. 원고에 원인 단정을 추가할 필요도 없다.

이 사례 때문에 새 임계값을 골라 성능을 다시 만들 필요는 없다. 이미 평가한 규칙을 유지하면서 설명을 저장 결과와 일치시키면 된다.

## 4. 정본·정정 기록·PDF 확인 범위

HWPX를 직접 열어 구조 검증을 수행했고 오류가 없었다. MD와 비교한 본문·제목·캡션의 누락은 없었으며, v7 대비 본문 텍스트 변경은 안내된 세 문단뿐이다. 전체 문단 568개·표 객체 22개·그림 4개이고, 그림 바이트와 모든 MD 표 행은 v7과 동일하다. 초록은 공백 기준 150단어다. 정정 기록의 기존 JSON 산출물과 로그는 보존돼 있으며, 해시로 식별된다.

PDF는 14쪽이다. 표가 있는 3·5·6·7·8·9·10·11쪽을 시각적으로 확인했다. Table 7은 10쪽 오른쪽 단, Table 8은 11쪽 왼쪽 단에 온전히 놓인다. 10쪽의 넓은 여백과 13쪽의 빈 오른쪽 단은 최종 편집에서 다듬을 여지가 있지만 표 나눔 문제는 해결됐다. 13·14쪽의 결론·후기·참고문헌도 확인했다.

HWPX의 나눔 방지 속성과 DOCX의 행 연결 속성은 실제 산출물에서 확인했다. 다만 제공 PDF는 LibreOffice가 DOCX에서 만든 근사본이다. 한컴오피스에서 HWPX를 직접 렌더링한 결과까지 확인한 것은 아니다.

이번 검토는 수정된 내용과 새 사례 설명을 확인한 재검토다. v6의 전체 모델·분할 감사나 v7의 모든 잔차 계산을 불필요하게 반복하지 않았고 새 학습·추론도 하지 않았다. 검증 기록은 같은 폴더의 `근거대조.json`, 사례별 실제 판정은 `학습세션_판정재확인.json`에 남겼다.

## 5. 다음 작업

1. 답변서와 대응 기록에서 위 학습 세션의 ‘19장’ 설명을 정정한다. 해당 설명이 없는 원고 본문과 표의 수치는 유지한다.
2. 저자·소속·교신저자, 후기의 사업명 자리표시자를 실제 정보로 채운다.
3. 한글에서 최종 제출 PDF를 만들고 표·수식·쪽 배치를 확인한다.

공통 미학습 조건의 추가 폴드·시드와 더 강한 미등록 검출 기준선을 이번 투고에서 제외한다는 결정은 현재의 제한된 주장 범위와 맞는다. 심사에서 요구될 가능성은 남지만, 이를 지금의 필수 보완으로 되돌리지 않는다. 위 기록 교정 후에는 연구를 계속 확대하기보다 제출본을 확정하는 단계로 넘어가는 것이 적절하다.
