현재 Isaac Sim에서 가상으로 생성한 데이터셋을 기반으로 학습된 모델을 **실제 환경**에 배포하기 위한 가이드입니다.

| 데이터 타입 | RGB + Depth |
| 학습 모델 | 분류 (Classification) + 6DoF Pose Estimation |
| 데이터 소스 | Isaac Sim 시뮬레이션 |

## 3. Sim-to-Real 전략

### 💡 핵심 질문: 실제 환경에서 카메라-부품 위치를 알아야 하나?

| 단계 | GT 필요 여부 | 설명 |
|------|-------------|------|
| **학습 (Training)** | ✅ 필요 | 정답(카메라-부품 위치)을 알아야 모델 학습 가능 |
| **추론 (Inference)** | ❌ 불필요 | 학습된 모델이 이미지만 보고 pose 예측 |

### 🎯 실제 환경에서 학습 데이터를 얻는 방법들

#### **방법 1: Sim-to-Real Transfer (권장) 🏆**

```
┌─────────────────────────────────────────────────────────────┐
│  시뮬레이션에서 학습 → 실제 환경에서 바로 사용              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [시뮬레이션]                    [실제]                     │
│  ┌───────────┐                   ┌───────────┐             │
│  │ RGB+Depth │ ──학습──> 모델 ──> │ RGB+Depth │ ──> Pose   │
│  │ + GT Pose │                   │ (카메라)  │             │
│  └───────────┘                   └───────────┘             │
│                                                             │
│  ✅ 장점: GT 라벨링 불필요, 대량 데이터 생성 가능           │
│  ⚠️ 단점: Domain Gap (시뮬레이션과 실제 차이)              │
└─────────────────────────────────────────────────────────────┘
```

**Domain Gap 줄이기:**
- 조명 랜덤화, 배경 랜덤화, 카메라 위치 랜덤화
- 실제 ZED 카메라의 특성(노이즈, 해상도)을 시뮬레이션에 추가

#### **방법 2: 마커 기반 GT 생성**

```
┌─────────────────────────────────────────────────────────────┐
│  ArUco/AprilTag 마커로 정확한 위치 계산                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│         [실제 부품]                                         │
│            ▲                                                │
│      ┌─────┴─────┐                                         │
│      │  ArUco    │  ← 마커 부착                            │
│      │  마커들   │                                         │
│      └───────────┘                                         │
│            │                                                │
│            ▼                                                │
│       카메라로 촬영                                         │
│            │                                                │
│            ▼                                                │
│   마커 검출 → 카메라-부품 상대 pose 계산                   │
│                                                             │
│  ✅ 장점: 실제 데이터로 정확한 GT 획득                     │
│  ⚠️ 단점: 마커 부착 필요, 추론 시에는 마커 없이 사용       │
└─────────────────────────────────────────────────────────────┘
```

#### **방법 3: 로봇 팔 + 정밀 측정**

```
┌─────────────────────────────────────────────────────────────┐
│  산업용 로봇 팔의 정밀 위치 제어 활용                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   [로봇 팔]                                                 │
│      │                                                      │
│      ├──> 그리퍼로 부품 파지 (위치 정확히 알고 있음)       │
│      │                                                      │
│   [카메라]                                                  │
│      │                                                      │
│      ├──> Hand-Eye Calibration (카메라-로봇 관계 보정)     │
│      │                                                      │
│      ▼                                                      │
│   로봇 위치 → 부품 위치 → GT Pose                          │
│                                                             │
│  ✅ 장점: 매우 정밀한 GT (산업용 환경에 적합)              │
│  ⚠️ 단점: 장비 비용, 설정 복잡                            │
└─────────────────────────────────────────────────────────────┘
```

### 💡 권장 전략

```
현재 시뮬레이션 데이터로 학습된 모델
            │
            ▼
     실제 ZED 카메라로 촬영
            │
            ▼
       모델 추론 (Pose 예측)
            │
            ▼
     결과가 괜찮은가? ──Yes──> 바로 사용!
            │
            No
            ▼
     Fine-tuning 필요 (방법 2 또는 3)
```

| 작업 | RGB | Depth | 핸드폰 가능 | ZED 필요 |

### 📱 분류(인식) 학습 데이터 - 핸드폰 OK!

```
┌─────────────────────────────────────────────────────────────┐
│  분류 모델 (Classification)                                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  입력: RGB 이미지만                                         │
│  출력: "이 부품은 Boom이다" (클래스 라벨)                   │
│                                                             │
│  ┌────────────┐                                             │
│  │  📱 핸드폰 │ → [RGB 이미지] → 모델 → "Boom" (95%)        │
│  │   촬영    │                        "Bucket" (3%)        │
│  └────────────┘                        "Arm" (2%)          │
│                                                             │
│  ✅ Depth 불필요                                            │
│  ✅ 핸드폰 카메라로 충분                                    │
```

### 📱 핸드폰 촬영 장점

| 장점 | 설명 |
|------|------|
| **접근성** | 누구나 보유, 별도 장비 불필요 |
| **고해상도** | 최신폰 4K 이상 촬영 가능 |
| **대량 수집** | 여러 사람이 동시에 촬영 가능 |
| **다양한 환경** | 다양한 조명/각도 자연스럽게 확보 |
| **저비용** | 장비 추가 비용 ₩0 |

### 🎬 핸드폰 촬영 가이드 (분류용)

**동영상 촬영 → 프레임 추출 방식:**

```python
# 동영상에서 프레임 추출 예시
import cv2

video = cv2.VideoCapture("부품_촬영.mp4")
frame_count = 0

while True:
    ret, frame = video.read()
    if not ret:
        break
    
    # 1초에 2-3프레임 정도만 저장 (중복 방지)
    if frame_count % 15 == 0:  # 30fps 기준
        cv2.imwrite(f"frame_{frame_count:04d}.jpg", frame)
    
    frame_count += 1
```

**촬영 팁:**

1. **다양한 각도**
   - 정면, 측면, 위, 아래, 대각선
   - 부품 주위를 360° 돌면서 촬영

2. **다양한 거리**
   - 가까이 (디테일)
   - 멀리 (전체 형태)

3. **다양한 조명**
   - 실내 형광등
   - 야외 자연광
   - 그림자가 있는 환경

4. **다양한 배경**
   - 공장 바닥
   - 작업대 위
   - 야외 지면

5. **해상도**
   - 최소 1080p 권장
   - 4K면 더 좋음 (나중에 crop/resize 가능)

### ⚠️ 참고사항

**1. 분류 추론도 ZED 필요한가?**

## 8. 부품 중심 정의

### 📍 부품 중심(Object Center)이란?

본 시스템에서 `camTobj`의 위치값이 가리키는 **"부품 중심"**은 다음과 같이 정의됩니다:

> **부품 중심 = CAD 모델의 3D AABB(Axis-Aligned Bounding Box)의 기하학적 중심**

### 🎯 세 가지 "중심" 비교

| 중심 유형 | 정의 | 사용 여부 |
|----------|------|----------|
| **2D BBox 중심** | 이미지 상 경계 박스의 중심 (픽셀 좌표) | ❌ 사용 안 함 |
| **CAD 원점** | USD 파일 설계 시 정의된 로컬 원점 | ❌ 사용 안 함 |
| **3D AABB 중심** | 모든 mesh 정점의 min/max 박스 중심 | ✅ **사용** |

### 📐 계산 방식

```python
# 01_generate_mult_class_dataset_with_pos.py의 compute_world_aabb 함수
def compute_world_aabb(stage):
    # 모든 Mesh 정점을 순회
    for prim in mesh_prims:
        pts = mesh.GetPointsAttr().Get()  # CAD 모델의 모든 정점
        for p in pts:
            world_min = min(world_min, wp)  # 최소 좌표
            world_max = max(world_max, wp)  # 최대 좌표
    
    # AABB 중심 계산
    center = (world_min + world_max) / 2.0  # ← 부품 중심
    return center
```

### 📊 시각화

```
┌─────────────────────────────────────────────────────────────┐
│                    3D AABB 중심 계산                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│        CAD 원점 (설계 기준점)                               │
│            ○                                               │
│            │                                                │
│   ┌────────┼──────────────────┐                            │
│   │        │                  │ ← 3D AABB (모든 정점 포함)  │
│   │        │     ●───────────→│ 3D AABB 중심              │
│   │        │    (부품 중심)    │ = (min + max) / 2          │
│   │   ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓    │ ← 부품 Mesh                 │
│   └───────────────────────────┘                            │
│                                                             │
│   world_min ─────────────────────────── world_max          │
│   center = (world_min + world_max) / 2  ← camTobj의 기준점 │
└─────────────────────────────────────────────────────────────┘
```

### ✅ 왜 이 방식이 유효한가?

**핵심 원리: 일관된 정의**

| 단계 | 부품 중심 정의 | 설명 |
|------|---------------|------|
| **학습** | 3D AABB 중심 | 모델이 이 위치를 예측하도록 학습됨 |
| **추론** | 모델 예측값 | 모델은 동일하게 "AABB 중심"을 예측 |
| **로봇** | 예측값 사용 | 부품의 대략적 중심 위치 획득 |

→ **학습과 추론에서 동일한 정의를 사용하면 일관성 유지**

### 📍 왜 CAD 원점 대신 AABB 중심을 사용하는가?

#### 1. CAD 원점의 문제점

| 문제 | 설명 |
|------|------|
| **비표준** | 설계자마다 원점 위치가 다름 (모서리, 면 중심, 기능점 등) |
| **실제 센서에서 불가** | Depth 카메라로는 CAD 원점 위치를 알 수 없음 |
| **일관성 없음** | 부품마다 다른 기준 → 학습 혼란 |

#### 2. AABB 중심의 장점

| 장점 | 설명 |
|------|------|
| **표준화** | 모든 부품에 동일한 방식으로 계산 |
| **실제 센서에서 가능** | Depth → Point Cloud → AABB 중심 계산 가능 |
| **일관성** | 시뮬레이션과 실제 환경에서 동일한 정의 |
| **직관적** | 부품의 "대략적인 가운데" = 로봇 제어에 실용적 |

```
시뮬레이션 (학습)          실제 환경 (추론)
     │                          │
     ▼                          ▼
CAD Mesh → AABB 중심      Depth → Point Cloud → AABB 중심
     │                          │
     └────── 동일한 방식 ───────┘
                │
                ▼
         모델 예측 일관성 보장
```

### 📐 3D 자세(회전)는 어떻게 추정하는가?

#### 위치 vs 회전의 차이

| 항목 | 위치 (t_xyz_m) | 회전 (r_xyz_deg) |
|------|---------------|------------------|
| **시뮬레이션** | AABB 중심 직접 계산 | 카메라 회전의 역으로 계산 |
| **실제 환경** | Depth에서 계산 가능 | **딥러닝 모델이 패턴으로 예측** |
| **기준점** | AABB 중심 | CAD 좌표계 방향 |

#### 회전 추정 방식

**현재 접근법: Sim-to-Real**

```
┌─────────────────────────────────────────────────────────────┐
│  모델이 이미지 패턴을 학습하여 회전을 예측                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [시뮬레이션 학습]                                          │
│  - 다양한 카메라 각도에서 촬영                              │
│  - 각 이미지에 대해 camTobj 회전 라벨 제공                  │
│  - 모델: "이 이미지 패턴이면 회전은 (10°, -5°, 30°)"       │
│                                                             │
│  [실제 추론]                                                │
│  - 모델이 이미지 패턴을 보고 회전을 예측                    │
│  - 명시적으로 CAD 좌표계를 찾지 않음                        │
│  - 학습된 패턴 매칭으로 추정                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**정밀도 향상이 필요한 경우:**
- ICP (Iterative Closest Point) 정합: CAD 모델과 Point Cloud 정합
- 특징점 기반: 부품의 keypoint 검출 후 PnP 알고리즘 적용

### 🎯 일관성의 핵심 원리

> **"정의가 일관되면, 출력도 일관된다"**

```
┌─────────────────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────────────────┤

│         │                            │                              │
│         ▼                            ▼                              │
│   ┌───────────────────────────────────────┐                        │
```

|------|------------------|-------------|------|
| **위치 정의** | AABB 중심 | AABB 중심 (모델 예측) | ✅ 일관 |

| **좌표계** | 카메라 좌표계 | 카메라 좌표계 | ✅ 일관 |

### ⚠️ 필수 요구사항: 좌표계 변환 (Hand-Eye Calibration)

AI 모델은 **카메라 좌표계**로 예측하지만, 용접 로봇은 **로봇 좌표계**를 사용합니다.

```
┌─────────────────────────────────────────────────────────────┐

│                                                             │
│  AI 예측 출력: 카메라 좌표계 (camTobj)                       │
│  ┌─────────────┐                                            │
│  │ X: 1.5m     │  ← 카메라 기준 오른쪽                      │
│  │ Y: 0.3m     │  ← 카메라 기준 아래쪽                      │
│  │ Z: 2.0m     │  ← 카메라 기준 앞쪽                        │
│  └─────────────┘                                            │
│         │                                                    │
│         ▼ 변환 행렬 (T_robot_camera)                         │
│         │                                                    │
│  로봇 좌표계                                                 │
│  ┌─────────────┐                                            │
│  │ X: 0.8m     │  ← 로봇 기준 X                             │
│  │ Y: 1.2m     │  ← 로봇 기준 Y                             │
│  │ Z: 0.5m     │  ← 로봇 기준 Z                             │
│  └─────────────┘                                            │
└─────────────────────────────────────────────────────────────┘
```

### 📝 좌표 변환 코드 예시

```python
import numpy as np

def camera_to_robot(camTobj, T_robot_camera):
    """
    카메라 좌표계 → 로봇 좌표계 변환
    
    Args:
        camTobj: 카메라 좌표계에서 부품 위치 (AI 예측값) [x, y, z]
        T_robot_camera: 카메라→로봇 변환 행렬 (4x4, 캘리브레이션으로 획득)
    
    Returns:
        로봇 좌표계에서 부품 위치 [x, y, z]
    """
    pos_camera = np.array([camTobj[0], camTobj[1], camTobj[2], 1.0])
    pos_robot = T_robot_camera @ pos_camera
    return pos_robot[:3]
```

### 🔧 용접 포인트 오프셋 정의

부품 중심(AABB 중심) ≠ 실제 용접 위치이므로, 클래스별 오프셋을 정의합니다.

```
┌─────────────────────────────────────────────────────────────┐
│  부품 중심 (AI 예측) vs 용접 포인트                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│          [부품 형상]                                        │
│     ┌─────────────────────┐                                │
│     │                     │                                │
│     │    ● AABB 중심      │  ← AI가 예측하는 위치          │
│     │    (부품 중심)       │                                │
│     │                     │                                │
│     └──────┬──────────────┘                                │
│            │                                                │
│            │← 용접 심 (용접할 위치)                         │
│     ═══════╧═══════════════                                │
│                                                             │
│  용접 포인트 = 부품 중심 + 오프셋                           │
└─────────────────────────────────────────────────────────────┘
```

### 📝 클래스별 용접 오프셋 코드 예시

```python
# 클래스별 용접 포인트 오프셋 정의 (예시)
WELDING_OFFSETS = {
    "arm_link_25_nomat": {
        "weld_point_1": (0.5, 0.0, -0.3),   # 중심에서 0.5m 우측, 0.3m 아래
        "weld_point_2": (-0.5, 0.0, -0.3),  # 중심에서 0.5m 좌측, 0.3m 아래
    },
    "arm_link_30_notmat": {
        "weld_point_1": (0.6, 0.0, -0.35),
        "weld_point_2": (-0.6, 0.0, -0.35),
    },
    "boom_link_25_nomat": {
        "weld_point_1": (0.0, 0.3, -0.2),
        "weld_point_2": (0.0, -0.3, -0.2),
    },
    "boom_link_30_notmat": {
        "weld_point_1": (0.0, 0.35, -0.25),
        "weld_point_2": (0.0, -0.35, -0.25),
    },
}

def get_welding_position(part_class, part_center, part_rotation, weld_point_id):
    """
    부품 중심에서 용접 포인트 계산
    
    Args:
        part_class: 부품 클래스명
        part_center: AI가 예측한 부품 중심 위치 (로봇 좌표계)
        part_rotation: AI가 예측한 부품 자세 (roll, pitch, yaw)
        weld_point_id: 용접 포인트 ID
    
    Returns:
        용접 로봇이 이동할 위치
    """
    offset = np.array(WELDING_OFFSETS[part_class][weld_point_id])
    
    # 부품 자세에 따라 오프셋도 회전 적용
    rotated_offset = apply_rotation(offset, part_rotation)
    
    # 용접 위치 = 부품 중심 + 회전된 오프셋
    weld_position = np.array(part_center) + rotated_offset
    
    return weld_position
```

### 📊 정밀도 요구사항

| 용접 유형 | 요구 정밀도 | AI 달성 가능성 |
|----------|------------|---------------|
| 대형 구조물 용접 | ±5~10mm | ✅ 가능 |
| 일반 용접 | ±2~5mm | ⚠️ 도전적 |
| 정밀 용접 | ±1mm 이하 | ❌ 추가 보정 필요 |

**굴삭기 부품 (대형 구조물)**: ±10mm 정밀도면 대부분 충분

### ✅ 용접 로봇 적용 체크리스트

| 항목 | 필요 여부 | 설명 |
|------|----------|------|
| **좌표계 변환** | ✅ 필수 | 카메라 → 로봇 좌표계 캘리브레이션 |
| **용접 포인트 오프셋** | ✅ 필수 | 부품 중심 → 실제 용접 위치 변환 |
| **정밀도 검증** | ✅ 권장 | 실제 환경에서 오차 측정 |
| **자세(회전) 활용** | ✅ 권장 | 부품 방향에 따라 용접 경로 조정 |

### 🎯 전체 워크플로우 요약

```
AI 예측 (부품 AABB 중심, 카메라 좌표계)
         │
         ▼
좌표 변환 (카메라 → 로봇 좌표계)
         │
         ▼
용접 오프셋 적용 (부품 중심 → 용접 포인트)
         │
         ▼
용접 로봇 이동 → 용접 수행
```
