2 **부품 인식 및 위치 추정 데이터 항목 정의 및 AI 모델 구축을 위한 기술조사**
    - 공정 흐름 기반의 부품 인식 및 위치 추정을 위한 데이터 항목 정의

    굴착기 제조 공정에서 부품 인식 및 위치 추정에 필요한 데이터 항목을 아래와 같이 정의하였다.

    [부품 분류 데이터 항목]
    · RGB 이미지: 1920×1080 해상도, 8-bit PNG 형식
    · Depth 이미지: 16-bit PNG 형식, 밀리미터(mm) 단위로 저장
    · RGBD 4채널 텐서: RGB 3채널 + Depth 1채널을 결합한 [Batch, 4, 224, 224] 형식의 모델 입력
    · 클래스 레이블: 굴착기 모델별(E25/E30/E38) × 부품 유형별(door_RH, door_LH_FRT, door_LH_RR) 
      총 8클래스 체계 (E30/E38 door_RH는 동일 부품으로 통합)
    · 메타데이터: 클래스명, 촬영 환경, 해상도, 카메라 정보, 데이터 소스(실물/합성) 등을 
      dataset_info.json(전체)과 metadata.json(클래스별)의 계층적 JSON 구조로 관리

    [위치 추정 데이터 항목]
    · 6DoF 포즈 정보: 카메라 기준 위치(t_xyz, 미터 단위) + 자세(q_xyzw, 쿼터니언)
    · 2D 바운딩 박스: [x_min, y_min, x_max, y_max] 형식의 픽셀 좌표
    · 카메라 내부 파라미터(K 행렬): 초점거리(fx, fy), 주점 좌표(cx, cy)
    · 가림 비율(occlusion ratio): 0.0(완전 보임) ~ 1.0(완전 가려짐)

    데이터 항목은 분류용 데이터셋(datasets/)과 6DoF 포즈용 데이터셋(dataset_pos/)의 두 가지 
    유형으로 구분하여 정의하였으며, 각각의 목적에 맞는 어노테이션 형식을 설계하였다.

    - AI 모델 구축을 위한 하이퍼파라미터 및 학습 데이터 전처리 기법 조사

    [모델 아키텍처 선정]
    부품 분류 모델로 ResNet18을 선정하였다. ImageNet 사전학습 가중치를 활용한 전이학습(Transfer 
    Learning) 방식을 채택하여, 소규모 데이터셋에서도 안정적인 학습 수렴을 확보하였다. RGBD 4채널 
    입력 지원을 위해 첫 번째 합성곱 레이어를 3채널→4채널로 확장하고, 추가 Depth 채널은 기존 RGB 
    3채널 가중치의 평균값으로 초기화하여 학습 안정성을 확보하였다. 출력 레이어는 Dropout(0.5) → 
    Linear(512→256) → ReLU → Dropout(0.3) → Linear(256→클래스 수) 구조로 설계하였다.

    [하이퍼파라미터 설정]
    · 옵티마이저: Adam (학습률 0.001)
    · 학습률 스케줄러: ReduceLROnPlateau (patience=5, factor=0.1)
    · 배치 크기: 64 (RTX 5090 GPU 메모리 기준 자동 조정)
    · 최대 에포크: 60 (Early Stopping patience=10으로 과적합 방지)
    · 손실 함수: CrossEntropyLoss (클래스 불균형 가중치 적용)
    · 데이터 분할: Train 80% / Test 20% (Stratified Split으로 클래스 비율 유지)

    [전처리 기법]
    · RGB 정규화: ImageNet 통계값 적용 (mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
    · Depth 정규화: 5m 기준 클리핑 → [0, 1] 스케일링 후 (x - 0.5) / 0.25 표준화
    · 이미지 리사이즈: 단변 기준 224px 리사이즈 → CenterCrop 224×224 적용
    · 블러 필터링: Laplacian Variance 기반 선명도 점수를 산출하고, 임계값(100) 미만의 흐릿한 
      이미지를 자동 제거하여 학습 데이터 품질 확보

    - 데이터 증강 기법 및 모델 경량화 기술 조사

    [데이터 증강 기법]
    소규모 실물 데이터셋의 한계를 극복하기 위해 온라인/오프라인 두 가지 방식의 증강 기법을 
    적용하였다.

    (1) 온라인 증강 (학습 시 실시간 적용)
    · 공간 변환: RandomRotation(±5°) — RGB·Depth에 동일 변환을 적용하여 기하학적 일관성 유지
    · 색상 변환: Brightness(0.7~1.3), Contrast(0.7~1.3), Saturation(0.8~1.2) 랜덤 조정
      (RGB에만 적용, Depth는 물리적 거리값이므로 변환하지 않음)

    (2) 오프라인 증강 (합성 데이터 생성 시 적용)
    · 도메인 랜덤화: Isaac Sim에서 배경(없음 20%/단색 30%/팩토리 50%), 조명 방향, 카메라 
      위치·각도를 랜덤화하여 실 환경 일반화 능력 향상

    [모델 경량화 기술]
    · ONNX 변환: PyTorch 모델을 ONNX 형식(opset 18)으로 변환하여 엣지 장비(Jetson Orin) 
      배포를 위한 크로스 플랫폼 호환성을 확보
    · TensorRT 변환 시도: ONNX → TensorRT 변환을 진행하였으나, Jetson 환경(aarch64, 
      TensorRT 10.3)에서 커스텀 fc 레이어의 출력 불일치 문제 발견. 정확도가 100%→32%로 
      하락하는 치명적 문제를 확인하고, 현재는 PyTorch 직접 추론으로 운영 (CPU 86ms/장)
    · 향후 NVIDIA 공식 Jetson PyTorch wheel 적용 시 GPU 추론 전환으로 ~10ms/장 수준까지 
      성능 향상이 가능할 것으로 예상

3 **학습 데이터 수집을 위한 하드웨어 장치 선정**
    - 부품 인식을 위한 카메라 및 센서 종류 분석

    굴착기 부품 인식에 적합한 카메라 및 센서를 3가지 유형으로 분류하여 분석하였다.

    (1) RGB 카메라
    산업용 GigE/USB3 카메라, 웹캠 등 일반 RGB 카메라는 비용이 저렴하고 해상도·프레임 레이트가 
    높으나, 깊이(Depth) 정보를 제공하지 못하여 3D 위치 추정이 불가능하다.

    (2) RGB-D 카메라 (깊이 센서 내장)
    · 스테레오 비전 방식: 두 개의 카메라로 시차(disparity)를 계산하여 깊이 추정. 야외 환경에서도 
      동작하나 텍스처 없는 표면에서 정확도가 저하됨.
      대표 제품: Stereolabs ZED 시리즈, Intel RealSense D400 시리즈
    · ToF(Time-of-Flight) 방식: 적외선 빛의 비행 시간으로 깊이 측정. 균일한 깊이맵을 
      제공하나 태양광 간섭에 취약함.
      대표 제품: Microsoft Azure Kinect, Intel RealSense L515
    · 구조광(Structured Light) 방식: 패턴 투사 후 변형을 분석하여 깊이 측정. 실내 
      근거리에서 높은 정확도를 보이나 야외 환경 사용이 제한됨.
      대표 제품: Intel RealSense SR300, Orbbec Astra

    (3) LiDAR 센서
    레이저 기반의 정밀 거리 측정이 가능하나, 단가가 높고 RGB 정보를 별도 카메라와 융합해야 
    하는 제약이 있다.

    본 과제에서는 부품의 외관(RGB)과 형상(Depth)을 동시에 활용하는 RGBD 4채널 기반 분류 
    모델을 설계하였으므로, RGB-D 카메라를 핵심 센서로 선정하였다.

    - 주요 제품 스펙 비교를 통한 최적 장비 선정

    RGB-D 카메라 3종의 주요 스펙을 비교 분석하여 최적 장비를 선정하였다.

    [주요 제품 스펙 비교]

    │ 항목           │ ZED X Mini       │ Intel RealSense D455 │ Microsoft Azure Kinect│
    ├────────────────┼──────────────────┼──────────────────────┼───────────────────────┤
    │ 깊이 측정 방식 │ 스테레오 비전    │ 스테레오 비전 + IR    │ ToF + RGB             │
    │ RGB 해상도     │ 1920×1200        │ 1280×800             │ 3840×2160             │

    │ Depth 범위     │ 0.1 ~ 15m        │ 0.6 ~ 6m             │ 0.25 ~ 5.46m          │
    │ FPS            │ 30/60            │ 30/90                │ 30                    │
    │ 인터페이스     │ GMSL2            │ USB-C 3.1            │ USB-C 3.0             │
    │ AI 깊이 추정   │ Neural Depth 지원│ 미지원               │ 미지원                │

    └────────────────┴──────────────────┴──────────────────────┴───────────────────────┘

    [선정 결과: Stereolabs ZED X Mini]
    선정 근거:
    · GMSL2 인터페이스로 NVIDIA Jetson 플랫폼과 네이티브 연동 가능
    · Neural Depth 모드: AI 기반 깊이 추정으로 스테레오 비전의 한계(텍스처 없는 면, 반사면) 극복
    · IP66 등급 방진방수로 제조 현장 환경(분진, 습기)에 적합
    · 높은 RGB/Depth 동시 해상도(1920×1200)로 정밀한 부품 형상 인식 가능
    · ZED SDK Python API(pyzed) 제공으로 빠른 소프트웨어 개발 지원

    [컴퓨팅 장비 선정]
    · 학습 서버: NVIDIA RTX 5090 GPU (CUDA 12.4) — 대규모 데이터셋 고속 학습
    · 추론 장비: NVIDIA Jetson Orin + ZED Box Mini — 현장 실시간 추론 (86ms/장, CPU)
    · 시뮬레이션: NVIDIA Isaac Sim 구동용 GPU 워크스테이션 — CAD 합성 데이터 생성

4 **학습 데이터 수집을 위한 서버 및 DBMS 환경 구축**
    - 카메라/센서 연동을 위한 신호처리 소프트웨어 설계

    ZED X Mini 카메라로부터 RGB+Depth 영상 신호를 실시간으로 수집·처리·저장하기 위한 
    소프트웨어 시스템을 설계·구현하였다.

    [시스템 아키텍처]
    ZED X Mini (GMSL2)
        → ZED SDK (pyzed.sl) — Neural Depth 모드, mm 단위
            → CameraManager (스레드 기반 비동기 캡처)
                → Flask 웹 서버 (포트 5000)
                    ├── MJPEG 실시간 스트리밍 (브라우저 모니터링)
                    ├── 비디오 녹화 + N 프레임 간격 자동 추출
                    ├── Laplacian Variance 블러 필터링 (흐릿한 프레임 자동 제거)
                    ├── 이미지 선별 큐레이션 UI (그리드 표시, 체크/해제)
                    └── RGB + Depth 쌍 동기 저장 (png 형식)

    [핵심 모듈 구성]
    · CameraManager: 스레드 기반 비동기 프레임 캡처 모듈. ZED SDK의 grab() → retrieve_image 
      (RGB) + retrieve_measure(Depth)를 통해 RGB·Depth를 동기화하여 획득한다. NaN/Inf 무효값 
      제거, BGRA→BGR 변환, float32→uint16 변환(16-bit PNG 저장) 등의 신호처리를 수행한다.
    · 품질 필터링 모듈: Laplacian Variance 기반 블러 점수를 산출하고, 임계값(100) 미만의 
      흐릿한 프레임을 자동 제거한다. 이를 통해 비디오 스트리밍 방식에서도 양질의 학습 
      이미지만 선별할 수 있다.
    · 웹 제어 인터페이스: Flask 기반 RESTful API로 설계하였다.
      /video_feed (GET): MJPEG 실시간 스트리밍
      /api/start_recording (POST): 녹화 시작 (클래스명, 프레임 추출 간격 지정)
      /api/stop_recording (POST): 녹화 정지 및 추출 결과 반환
      /api/snapshot (POST): 수동 1장 캡처
      /api/save_selected (POST): 선별된 이미지를 데이터셋으로 저장
      /api/dataset_status (GET): 클래스별 이미지 수집 현황 조회

    [OpenCV 폴백 지원]
    ZED SDK가 설치되지 않은 환경에서도 OpenCV 웹캠 폴백으로 RGB 데이터 수집이 가능하도록 
    설계하여, 개발 환경의 유연성을 확보하였다 (Depth는 None 반환).

    - 수집된 신호 데이터의 효율적 저장/관리를 위한 DBMS 스키마 설계

    수집된 RGB+Depth 이미지와 메타데이터, 학습·평가 이력을 체계적으로 관리하기 위한 관계형 
    데이터베이스 스키마를 설계하였다. 이미지 바이너리 파일은 파일시스템에 저장하고, 메타데이터·
    학습 이력·평가 결과는 RDBMS로 관리하는 하이브리드 구조를 채택하였다.

    [데이터베이스 테이블 구성 (9개 테이블)]
    · datasets: 데이터셋 단위 관리 (이름, 유형[실물/합성/혼합], 클래스 수, 파일시스템 경로)
    · classes: 클래스 정보 (클래스명, 굴착기 모델명, 부품 유형, CAD 확보 여부)
    · images: 개별 이미지 메타데이터 (RGB/Depth 파일 경로, 해상도, 블러 점수, 데이터 소스, 
      학습 분할(train/test), 유효 여부)
    · capture_sessions: 촬영 세션 이력 (카메라 종류, 촬영 방식, 프레임 추출 간격, 블러 임계값, 
      총/추출/유효 프레임 수)
    · models: 학습된 모델 관리 (아키텍처, 입력 채널 수, 가중치/ONNX/TRT 파일 경로)
    · training_sessions: 학습 세션 이력 (하이퍼파라미터, 최고 정확도, 학습 시간, GPU 정보)
    · training_metrics: 에포크별 학습 지표 (train_loss, val_loss, val_accuracy, learning_rate)
    · evaluation_results: 평가 결과 (정확도, Precision/Recall/F1, 혼동 행렬, 추론 시간)
    · augmentation_configs: 데이터 증강 설정 (적용 대상(RGB/Depth/Both), 파라미터 JSON)

    [주요 설계 특징]
    · 파일시스템-DB 하이브리드: 대용량 이미지는 파일시스템에 저장하되, 메타데이터와 경로만 
      DB에 기록하여 저장 효율과 관리 편의성을 동시에 확보
    · 이력 추적: 촬영 세션 → 이미지 → 학습 세션 → 평가 결과의 전체 생애주기를 추적 가능
    · 크로스 도메인 지원: evaluation_results의 eval_type 필드를 통해 동일 도메인(in_domain), 
      교차 도메인(cross_domain), 추론 파이프라인(inference_pipeline) 평가를 구분 관리
    · 인덱스 최적화: images, training_metrics 등 대량 데이터 테이블에 class_id, session_id, 
      data_source, split 등 빈번한 검색 컬럼에 인덱스를 설계

    상세 스키마(DDL, ER 다이어그램, 인덱스, 활용 쿼리 예시, 마이그레이션 전략)는 
    별도 문서 'DBMS_SCHEMA_DESIGN.md'에 기술하였다.

5 **부품 인식 AI 학습용 기초 데이터셋 구축**
    - 부품 인식 학습을 위한 모사 시험 환경 구축

    실물 부품 확보의 제약(도어 종류당 1장)을 극복하기 위해, NVIDIA Isaac Sim 기반의 
    디지털 트윈 모사 시험 환경을 구축하였다.

    [CAD 모델 변환 파이프라인]
    굴착기 도어 8종의 STEP(.stp) CAD 파일을 Isaac Sim이 인식하는 USD 형식으로 변환하는 
    자동화 파이프라인을 구축하였다 (STL → USD, Isaac Sim Asset Converter 활용). 단위는 
    밀리미터(mm)이며, 각 도어별로 카메라가 관찰해야 할 축 방향(+Z/-Z)을 메타데이터로 정의하였다.

    [가상 촬영 환경 구성]
    · 렌더링 엔진: Isaac Sim Replicator (물리 기반 렌더링)
    · 카메라 설정: 1024×1024 해상도, FOV 60°, 구면 좌표계 기반 랜덤 위치/각도 배치
    · 조명 설정: Dome Light (강도 1000, 회전 (270, 0, 0))
    · 데이터 출력: RGB(8-bit PNG) + Depth(16-bit PNG, mm 단위) 쌍으로 동시 생성

    [도메인 랜덤화(Domain Randomization)]
    실 환경으로의 일반화 능력을 확보하기 위해 아래 요소들을 랜덤화하였다.
    · 배경: 없음(20%), 단색(30%), 팩토리 배경(50%)을 랜덤 혼합
    · 카메라 위치: 수평 ±45°, 수직 15~75° 범위의 구면 좌표에서 랜덤 샘플링
    · 카메라 거리: 부품 대각선 길이 기반으로 계산된 범위 내 랜덤 배치
      (도어 전체가 프레임에 보이도록 fill 60%, ±8° 구도로 파라미터 최적화)
    · 조명: Dome Light 방향 변화

    이 모사 환경을 통해 실물 없이도 대규모 학습 데이터를 확보할 수 있으며, 
    CAD 사전학습 → 실물 Fine-tuning의 도메인 적응 전략이 가능해졌다.

    - 다양한 조건을 반영한 다중 형태 데이터 수집 및 전처리

    두 가지 경로(실물 촬영/CAD 합성)로 다중 형태의 RGBD 데이터를 수집하고, 통일된 
    전처리 파이프라인을 구축하였다.

    [경로 A — 실물 RGBD 데이터 수집]
    · 수집 장비: ZED X Mini 카메라 (Neural Depth 모드, HD1080, 30fps)
    · 수집 방식: Flask 웹 UI를 통한 비디오 스트리밍 + 프레임 추출 하이브리드 방식
    · 촬영 전략: 정면, 좌/우 45°, 좌/우 90°, 상/하 30° 등 다양한 시점에서 촬영하고, 
      0.5m~3m 거리 범위에서 원/근 다양한 스케일을 확보
    · 수집 현황: 3종 도어(E25/E30/E38 door_LH_FRT) 각 약 110장, 총 337장 RGBD 쌍 확보
    · 전처리: RGB → 8-bit PNG, Depth → 16-bit PNG(mm 단위), Laplacian 블러 필터링 적용

    [경로 B — CAD 합성 RGBD 데이터 생성]
    · 생성 도구: NVIDIA Isaac Sim + Omni Replicator
    · 생성 규모: 8클래스 × 500장 = 총 4,000장 RGBD 쌍
    · 생성 형식: RGB(8-bit PNG) + Depth(16-bit PNG, mm 단위)
    · 도메인 랜덤화: 배경, 카메라 위치/각도, 조명 방향을 매 프레임 랜덤화

    [통일 전처리 파이프라인 (depth_utils.py)]
    실물·합성 데이터 모두 동일한 전처리를 거쳐 모델에 입력된다.
    · RGB: Resize(단변 224px) → CenterCrop(224×224) → ImageNet 정규화
    · Depth: 5m 기준 클리핑 → [0, 1] 스케일링 → (x - 0.5) / 0.25 표준화
    · 결합: RGB 3채널 + Depth 1채널 → [Batch, 4, 224, 224] 텐서
    · Depth 파일 부재 시 0으로 채워 graceful degradation 지원

    - 데이터 증강(Data Augmentation) 기법 적용을 통한 학습용 데이터 다양성 확보

    소규모 실물 데이터셋(337장)의 한계를 극복하고 모델의 일반화 성능을 향상시키기 위해, 
    3단계 데이터 증강 전략을 수립·적용하였다.

    [1단계 — 온라인 증강 (학습 시 실시간 적용)]
    매 에포크마다 학습 이미지에 랜덤 변환을 적용하여 실질적 데이터 다양성을 확대하였다.
    · 공간 증강: RandomRotation(±5°) — RGB·Depth에 동일 회전 행렬을 적용하여 
      기하학적 일관성 유지 (Depth는 INTER_NEAREST 보간으로 값 보존)
    · 색상 증강: Brightness(0.7~1.3), Contrast(0.7~1.3), Saturation(0.8~1.2) — 
      RGB에만 적용하여 다양한 조명 환경 시뮬레이션 (Depth는 물리적 거리값이므로 제외)

    [2단계 — 오프라인 증강 (합성 데이터 도메인 랜덤화)]
    Isaac Sim의 Replicator를 활용하여 데이터 생성 단계에서 대규모 오프라인 증강을 수행하였다.
    · 배경 랜덤화: 배경 없음(20%) / 단색(30%) / 팩토리 배경(50%)을 랜덤 혼합
    · 카메라 위치 랜덤화: 구면 좌표계에서 랜덤 샘플링으로 다양한 시점 확보
    · 조명 랜덤화: Dome Light 방향 및 강도 변화
    · 결과: 8클래스 × 500장 = 4,000장의 도메인 랜덤화된 합성 RGBD 데이터 확보

    [3단계 — 크로스 도메인 전략 (Domain Adaptation)]
    CAD 합성 데이터와 실물 데이터 간의 도메인 격차를 해소하기 위한 전이학습 전략을 수립하였다.
    · 사전학습: CAD 합성 데이터(4,000장)로 부품 형상의 기본 특징을 학습
    · Fine-tuning: 소량의 실물 데이터(337장)로 실 환경 도메인에 적응
    · 크로스 도메인 평가: CAD로 학습한 모델을 실물 데이터로 평가하여 전이 가능성을 정량 검증

    [증강 효과 검증]
    실물 3종 분류에서 337장 원본 데이터만으로 100% 정확도(68/68)를 달성하였으며, 
    Precision/Recall/F1 모두 100%를 기록하였다. 합성 데이터 4,000장 추가를 통해 
    8클래스 확장 시에도 안정적인 학습이 가능함을 확인하였다. 실시간 추론 파이프라인 
    검증에서도 98.53%(67/68) 정확도와 평균 86ms/장의 추론 속도를 달성하여, 
    데이터 증강 전략의 유효성을 입증하였다.
