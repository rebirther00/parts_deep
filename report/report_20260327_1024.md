## 2. 부품 인식 및 위치 추정 데이터 항목 정의 및 AI 모델 구축을 위한 기술조사

### 2.1 공정 흐름 기반의 부품 인식 및 위치 추정을 위한 데이터 항목 정의

#### 2.1.1 연구 배경 및 목적

굴착기 제조 공정에서 부품의 자동 인식 및 위치 추정은 생산성 향상의 핵심 기술이다. 이를 위해서는 카메라·센서로부터 획득되는 영상 데이터와 AI 모델이 요구하는 입·출력 데이터의 형식, 구조, 단위 등을 명확히 정의하는 것이 선행되어야 한다.

본 연구에서는 1차년도에서 수립한 RGB 기반 부품 분류 데이터 체계를 확장하여, **RGBD 4채널 (RGB + Depth)** 기반의 데이터 항목을 새롭게 정의하였다. Depth 채널을 추가함으로써 부품의 외관 정보뿐만 아니라 3차원 형상 정보를 동시에 활용할 수 있게 되어, 형상이 유사한 부품 간의 분류 정확도를 향상시킬 수 있다.

### 2.2 AI 모델 구축을 위한 하이퍼파라미터 및 학습 데이터 전처리 기법 조사

#### 2.2.1 모델 아키텍처 선정

부품 분류를 위한 기반 모델로 **ResNet18**을 선정하였다. ResNet18은 18개 레이어로 구성된 잔차 학습(Residual Learning) 기반의 합성곱 신경망으로, 약 1,100만 개의 파라미터를 가진 경량 모델이다. ImageNet 데이터셋(1,000개 클래스, 128만 장)으로 사전학습된 가중치를 활용한 **전이학습(Transfer Learning)** 방식을 채택하여, 소규모 데이터셋(수백 장 수준)에서도 안정적인 학습 수렴과 높은 분류 정확도를 확보하였다.

**[RGBD 4채널 입력 확장]**

기존 ResNet18은 RGB 3채널 입력을 전제로 설계되어 있으므로, RGBD 4채널 입력을 지원하기 위해 첫 번째 합성곱 레이어(conv1)를 수정하였다. 구체적으로, 3채널 → 4채널로 확장된 새로운 Conv2d(4, 64, kernel_size=7, stride=2, padding=3) 레이어를 생성하고, 기존 ImageNet 사전학습 가중치의 RGB 3채널분은 그대로 복사하며, 추가된 Depth 채널(4번째)은 기존 RGB 3채널 가중치의 **평균값**으로 초기화하였다. 이를 통해 Depth 채널이 초기에 RGB 특징의 평균적 반응을 보이면서 안정적으로 학습을 시작할 수 있다.

```
RGBDAuxResNet18 모델 구조
═══════════════════════════════════════════════════════

입력 1: [Batch, 4, 448, 448]  (R, G, B, D)     입력 2: [Batch, 4]  (물리 치수)
      │                                              │
      ▼                                              ▼
┌─────────────────────────────────────────┐  ┌────────────────────────┐
│  Conv2d(4→64, 7×7, stride=2, pad=3)    │  │  Aux MLP               │
│  BatchNorm2d(64)                        │  │  Linear(4→16) + ReLU   │
│  ReLU                                   │  │  Linear(16→32)         │
│  MaxPool2d(3×3, stride=2)               │  │  → [Batch, 32]        │
├─────────────────────────────────────────┤  └───────────┬────────────┘
│  ResNet18 Residual Blocks               │              │
│  ├── Layer1: BasicBlock × 2 (64→64)     │              │
│  ├── Layer2: BasicBlock × 2 (64→128)    │              │
│  ├── Layer3: BasicBlock × 2 (128→256)   │              │
│  └── Layer4: BasicBlock × 2 (256→512)   │              │
├─────────────────────────────────────────┤              │
│  AdaptiveAvgPool2d → [Batch, 512]       │              │
└────────────────────┬────────────────────┘              │
                     │          ┌─────────────────────────┘
                     └──────────┤
                                ▼
                     Concatenate [512 + 32 = 544]
                                │
                                ▼
                     ┌───────────────────────┐
                     │  Dropout(0.5)         │
                     │  Linear(544→256)+ReLU │
                     │  Dropout(0.3)         │
                     │  Linear(256→N_class)  │
                     └───────────────────────┘
                                │
                                ▼
                     출력: [Batch, N_class] (로짓)
```

#### 2.2.2 하이퍼파라미터 설정

모델 학습에 사용된 하이퍼파라미터는 사전 실험을 통해 최적값을 탐색하여 결정하였다.

| 하이퍼파라미터 | 설정값 | 선정 근거 |
|--------------|--------|---------|
| 옵티마이저 | Adam | 적응적 학습률로 빠른 수렴, 하이퍼파라미터 튜닝 부담 감소 |
| 초기 학습률 | 0.001 | 전이학습 시 사전학습 가중치 보존에 적합한 중간 학습률 |
| 학습률 스케줄러 | ReduceLROnPlateau | 검증 손실 정체 시 자동 학습률 감소 (patience=5, factor=0.1) |
| 배치 크기 | 64 | RTX 5090 GPU(32GB VRAM) 메모리 기준 최적화, 자동 조정 지원 |
| 최대 에포크 | 60 | 과적합 방지를 위한 충분한 학습 기회 부여 |
| Early Stopping | patience=10 | 검증 정확도 10 에포크 연속 미개선 시 조기 종료 |
| 손실 함수 | CrossEntropyLoss | 다중 클래스 분류의 표준 손실 함수, 클래스 가중치 적용 |
| 클래스 가중치 | 역빈도 기반 | 클래스 불균형 보정 (이미지 수 적은 클래스에 높은 가중치) |
| 데이터 분할 | Train 80% / Test 20% | Stratified Split으로 클래스 비율 유지 |
| Dropout | 0.5 / 0.3 | FC 레이어 과적합 방지 (첫 번째: 0.5, 두 번째: 0.3) |

#### 2.2.3 학습 데이터 전처리 기법

수집된 원시 이미지 데이터를 모델에 입력하기 위한 전처리 파이프라인을 설계·구현하였다. 굴착기 부품(도어 등)은 좌·우 방향 및 형상의 **종횡비(aspect ratio)가 분류의 핵심 특징**이므로, 기존의 CenterCrop 방식 대신 **Letterbox 방식**을 채택하였다. Letterbox 방식은 장변을 기준으로 이미지를 축소한 뒤, 단변 방향에 검정(0) 패딩을 추가하여 정사각형을 완성하므로, 원본 이미지의 종횡비가 완전히 보존되어 부품의 형상 정보가 손실 없이 모델에 전달된다. RGB와 Depth 데이터의 특성이 상이하므로, 각각에 적합한 전처리 기법을 적용하되 공간 변환은 동기화하여 기하학적 일관성을 유지하였다.

**[입력 해상도 448×448 선정 근거]**

초기에는 ImageNet 표준인 224×224 해상도를 사용하였으나, 유사 형상 부품(E25/E30/E38 도어) 간 크기 차이가 40~50mm에 불과한 점이 문제가 되었다. 1920×1080 원본에서 224×224로 축소 시 약 8.6배 다운샘플링되어, 50mm 물리 차이가 약 6픽셀 미만으로 줄어들어 모델이 클래스를 구분하지 못하는 현상이 발생하였다(34% 정확도). 이에 해상도를 **448×448**로 2배 증가시켜 유효 픽셀 차이를 약 12픽셀 이상으로 확보하였다. 메모리 사용량은 4배 증가하나, RTX 5090(32GB VRAM) 기준 배치 크기 16에서 안정적으로 학습 가능하다.

**[전처리 파이프라인]**

```
원본 RGB (1920×1080, 8-bit)          원본 Depth (1920×1080, 16-bit, mm)
        │                                      │
        ▼                                      ▼
  PIL.Image 로드 (RGB)                  cv2.imread (UNCHANGED)
        │                                      │
        ▼                                      ▼
  ┌─────────────────────── 동기화 공간 변환 ───────────────────────┐
  │  1) Letterbox Resize: 장변 기준 448px 축소 (종횡비 보존)       │
  │  2) 중앙 배치 패딩: 검정(0) 패딩으로 448×448 완성             │
  │  3) [학습 시] HorizontalFlip(50%)                              │
  │  4) [학습 시] RandomRotation(±15°)                             │
  │  5) [학습 시] RandomScale(0.9~1.1, 50%)                       │
  │     ※ RGB·Depth 동기화: 동일 파라미터 적용                     │
  │     ※ Depth 보간: INTER_NEAREST (거리값 왜곡 방지)             │
  └────────────────────────────────────────────────────────────────┘
        │                                      │
        ▼                                      ▼
  [학습 시] 색상·노이즈 증강             5m 클리핑 → [0, 1] 스케일링
  - Brightness (0.6~1.4)                       │
  - Contrast (0.6~1.4)                         ▼
  - Saturation (0.7~1.3)             정규화: (x - 0.5) / 0.25
  - Hue (±0.05)
  - GaussianNoise (30%, σ=3~10)
  - GaussianBlur (20%, k=3)
        │                                      │
        ▼                                      ▼
  ToTensor → Normalize               ToTensor (unsqueeze)
  mean=[0.485, 0.456, 0.406]                   │
  std=[0.229, 0.224, 0.225]                    │
        │                                      │
        └────────── torch.cat ─────────────────┘
                       │
                       ▼
              [Batch, 4, 448, 448]
              (R, G, B, D 채널)

        ┌─────── Depth 기반 물리 치수 계산 ───────┐
        │  원본 Depth에서 전경(부품) 영역 검출      │
        │  → 카메라 내부 파라미터로 물리 치수 변환   │
        │  → [width_mm, height_mm, aspect, depth]  │
        └──────────────────────────────────────────┘
                       │
                       ▼
              [Batch, 4] 보조 피처 (Auxiliary Features)
```

|------------|----------|------|---------|------|

| Depth 클리핑 | Depth | 최대 거리 제한 | 5,000mm (5m) | 원거리 노이즈 제거 |
| Depth 스케일링 | Depth | 선형 스케일링 | ÷5000 → [0, 1] | 값 범위 통일 |

> **표 2-8.** 전처리 기법 상세

**[Depth 정규화 설계 근거]**

Depth 값은 물리적 거리(mm)를 나타내므로, RGB와는 다른 정규화 전략이 필요하다. 본 연구에서는 아래 3단계 정규화 방식을 채택하였다.

1. **클리핑**: 5m(5,000mm) 초과 값을 5m로 제한하여 원거리 노이즈 영향을 배제
2. **[0, 1] 스케일링**: 클리핑된 값을 5,000으로 나누어 0~1 범위로 정규화
3. **Z-score 표준화**: (x - 0.5) / 0.25 적용으로 평균 0, 표준편차 약 1의 분포로 변환

이 방식은 무효값(0, NaN, Inf)을 0.0으로 일관 처리하고, RGB 채널과 유사한 값 범위를 유지하여 합성곱 연산의 수치 안정성을 확보한다.

#### 2.2.4 Depth 기반 물리 치수 보조 피처 (Auxiliary Features)

굴착기 도어 부품은 E25/E30/E38 모델 간 40~50mm의 미세한 크기 차이만 존재하여, 이미지 픽셀 정보만으로는 분류가 어렵다. 이를 해결하기 위해 Depth 맵과 카메라 내부 파라미터(intrinsics)를 활용하여 **부품의 물리적 치수를 수치 피처로 직접 계산**하고, CNN 특징과 결합하는 방식을 도입하였다.

**[물리 치수 계산 원리]**

Depth 맵에서 전경(부품) 영역을 검출한 후, 카메라 핀홀 모델을 이용하여 픽셀 좌표를 실제 물리 좌표(mm)로 변환한다.

```
물리 좌표 변환 공식:
  X_mm = (x_pixel - cx) × depth_mm / fx
  Y_mm = (y_pixel - cy) × depth_mm / fy

  여기서 fx, fy = 초점거리, cx, cy = 주점(principal point)
```

| 보조 피처 | 계산 방법 | 단위 | 의미 |
|----------|----------|------|------|
| physical_width_mm | 전경 영역의 X 좌표 범위 (max - min) | mm | 부품의 실제 너비 |
| physical_height_mm | 전경 영역의 Y 좌표 범위 (max - min) | mm | 부품의 실제 높이 |
| aspect_ratio | width / height | 무차원 | 부품의 종횡비 |
| mean_depth_mm | 전경 영역의 평균 Depth 값 | mm | 부품까지의 평균 거리 |

> **표 2-8b.** Depth 기반 물리 치수 보조 피처

**[전경 영역 검출]**

Depth 맵에서 유효 범위(100mm ~ 3000mm) 내의 픽셀을 전경으로 판정한다. 이는 바닥면과 배경 노이즈를 제거하고 부품 영역만을 추출하기 위함이다. 전경 픽셀이 부족할 경우(100개 미만) 안전하게 0벡터를 반환하여 학습 안정성을 보장한다.

**[모델 아키텍처: RGBDAuxResNet18]**

기존 ResNet18 backbone의 512차원 CNN 특징에, 물리 치수 4개를 소규모 MLP(Multi-Layer Perceptron)로 처리한 32차원 피처를 연결(concatenate)하여 총 544차원의 복합 특징 벡터를 구성하고, 최종 분류기(FC)에 입력한다.

```
                ┌──────────────────────────┐
                │  RGBD 이미지 (4ch, 448²)  │
                │        ResNet18          │
                │  → 512차원 CNN 특징       │
                └────────────┬─────────────┘
                             │
          ┌──────────────────┼──────────────────┐
          │                  │                  │
          │    ┌─────────────┴─────────────┐    │
          │    │  물리 치수 (4개)            │    │
          │    │  → Linear(4→16) → ReLU    │    │
          │    │  → Linear(16→32)          │    │
          │    │  → 32차원 Aux 특징         │    │
          │    └─────────────┬─────────────┘    │
          │                  │                  │
          │           Concatenate               │
          │         [512 + 32 = 544]             │
          │                  │                  │
          │    ┌─────────────┴─────────────┐    │
          │    │  FC 분류기 (544 → N_class) │    │
          │    └───────────────────────────┘    │
          └────────────────────────────────────┘
```

> **그림 2-3b.** RGBDAuxResNet18 모델 아키텍처

이 접근법의 핵심 이점은 CNN이 학습하기 어려운 **절대적 물리 크기 정보**를 명시적 수치로 제공함으로써, 시각적으로 거의 동일한 형상의 부품도 40~50mm 크기 차이에 기반하여 정확히 분류할 수 있다는 점이다.

#### 2.3.1 데이터 증강 기법

실물 데이터셋(1,256장)의 한계를 극복하기 위해, 온라인(학습 시 실시간)과 오프라인(데이터 생성 시) 두 가지 방식의 데이터 증강 기법을 적용하였다.

**[온라인 증강 기법 (학습 시 실시간 적용)]**

매 에포크(epoch)마다 학습 이미지에 랜덤 변환을 적용하여 실질적 데이터 다양성을 확대한다. RGB와 Depth 간의 기하학적 일관성을 유지하기 위해, 공간 변환은 동일한 파라미터로 양쪽에 적용하고 색상·노이즈 변환은 RGB에만 적용한다.

> **표 2-11.** 모델 경량화 기술 적용 현황

**[ONNX 변환]**

학습된 PyTorch 모델을 ONNX(Open Neural Network Exchange) 형식(opset 18)으로 변환하여 플랫폼 독립적인 모델 배포를 지원하였다. 변환된 ONNX 모델의 크기는 약 43.13MB이며, 학습 서버(x86_64)에서 변환 후 추론 장비(aarch64, Jetson Orin)로 이식이 가능하다.

**[TensorRT 변환 시도 및 호환성 분석]**

ONNX 모델을 TensorRT 엔진으로 변환하여 GPU 가속 추론을 시도하였으나, **출력 불일치 문제**가 발생하였다. 동일한 입력에 대해 PyTorch와 TensorRT 엔진의 출력 차이가 최대 11.55에 달하였으며, TensorRT 엔진의 분류 정확도가 100%에서 32.35%로 하락하였다.

| 검증 항목 | PyTorch | TensorRT | 비고 |
|----------|---------|----------|------|
| 입력 데이터 차이 | - | **0** (동일) | 입력은 정확히 일치 |
| 출력 값 차이 (최대) | - | **11.55** | 완전히 다른 출력 |
| 분류 정확도 | 98.53% | 32.35% | 66%p 하락 |
| ONNX 파일 검증 | - | 정상 (가중치 내장) | 파일 자체는 문제 없음 |

> **표 2-12.** PyTorch vs TensorRT 출력 비교

**원인 분석**: Jetson Orin 환경(aarch64, TensorRT 10.3)과 PyTorch 2.10의 ONNX export 간 호환성 문제로 추정된다. 특히 커스텀 fc 레이어 구조(Dropout + Linear + ReLU + Dropout + Linear)가 TRT 최적화 과정에서 잘못 변환된 것으로 분석된다.

**현재 운영 방식**: PyTorch (.pth) 직접 추론으로 전환하여 운영 중이며, CPU 기준 86ms/장의 추론 속도로 0.5초 간격 실시간 추론에 충분한 성능을 확인하였다. 향후 NVIDIA 공식 Jetson PyTorch wheel 적용 시 GPU 추론으로 전환하여 ~10ms/장 수준의 성능 향상을 기대한다.

## 3. 학습 데이터 수집을 위한 하드웨어 장치 선정

### 3.1 부품 인식을 위한 카메라 및 센서 종류 분석

#### 3.1.1 분석 목적

굴착기 부품 인식 시스템에 적합한 센서를 선정하기 위해, 산업용 영상 센서를 유형별로 분류하고 각각의 특성, 장·단점, 적용 환경을 분석하였다. 본 과제에서는 부품의 외관(RGB)과 형상(Depth)을 동시에 활용하는 RGBD 4채널 기반 분류 모델을 설계하였으므로, RGB와 Depth를 동시에 제공하는 센서가 필수적이다.

#### 3.1.2 센서 유형별 분석

**[(1) RGB 카메라]**

산업용 GigE/USB3 카메라, 웹캠 등 일반 RGB 카메라는 비용이 저렴하고 해상도·프레임 레이트가 높으나, 깊이(Depth) 정보를 제공하지 못하여 3D 위치 추정이 불가능하다. 부품의 2D 분류에는 활용 가능하나, 형상이 유사한 부품(예: E30과 E38 도어의 47mm 크기 차이)의 구분에는 한계가 있다.

| 항목 | 내용 |
|------|------|
| 장점 | 고해상도(4K 이상), 높은 FPS(120+), 저가, 다양한 인터페이스(GigE/USB3/MIPI) |
| 단점 | Depth 정보 미제공, 3D 위치 추정 불가, 형상 기반 분류 한계 |
| 대표 제품 | FLIR Blackfly, Basler ace, Lucid Vision Triton |
| 적합 환경 | 2D 외관 검사, 바코드/QR 인식, 색상 기반 분류 |

> **표 3-1.** RGB 카메라 특성

**[(2) RGB-D 카메라 (깊이 센서 내장)]**

하나의 장치에서 RGB 컬러 이미지와 Depth(깊이) 맵을 동시에 제공하는 센서이다. 깊이 측정 방식에 따라 3가지로 세분화된다.

**(2-a) 스테레오 비전 방식**

두 개의 카메라(좌/우)로 촬영한 이미지의 시차(disparity)를 계산하여 깊이를 추정하는 방식이다. 야외 환경에서도 동작하며, 텍스처가 풍부한 대형 부품의 깊이 추정에 적합하다. 다만, 텍스처가 없는 매끈한 금속 표면에서는 시차 계산이 어려워 정확도가 저하될 수 있다.

| 항목 | 내용 |
|------|------|
| 측정 원리 | 좌/우 카메라 시차(disparity) → 삼각 측량 |
| 장점 | 원거리 측정 가능(15m+), 야외 사용 가능, AI 기반 깊이 보정 가능 |
| 단점 | 텍스처 없는 표면에서 정확도 저하, 최소 측정 거리 존재 |
| 대표 제품 | **Stereolabs ZED 시리즈**, Intel RealSense D400 시리즈 |

> **표 3-2.** 스테레오 비전 방식 특성

**(2-b) ToF (Time-of-Flight) 방식**

적외선 광원에서 방출된 빛이 물체에 반사되어 돌아오는 시간을 측정하여 깊이를 계산하는 방식이다. 센서 전체 영역에서 균일한 깊이맵을 제공하며, 텍스처에 무관하게 동작한다. 그러나 태양광 등 강한 적외선 간섭에 취약하여 야외 사용이 제한된다.

| 항목 | 내용 |
|------|------|
| 측정 원리 | IR 광 비행 시간 측정 (위상 차이 방식) |
| 장점 | 텍스처 무관, 균일한 깊이맵, 실시간 처리 가능 |
| 단점 | 태양광 간섭에 취약, 해상도 상대적으로 낮음, 멀티패스 오류 |
| 대표 제품 | Microsoft Azure Kinect, Intel RealSense L515 |

> **표 3-3.** ToF 방식 특성

**(2-c) 구조광 (Structured Light) 방식**

알려진 패턴(점, 줄무늬 등)을 물체에 투사하고, 변형된 패턴을 분석하여 깊이를 계산하는 방식이다. 실내 근거리에서 높은 정확도를 보이나, 야외 환경에서는 투사 패턴이 태양광에 의해 가려져 사용이 어렵다.

| 항목 | 내용 |
|------|------|
| 측정 원리 | 알려진 패턴 투사 → 변형 분석 → 깊이 계산 |
| 장점 | 근거리 고정확도, 미세 형상 측정 가능 |
| 단점 | 야외 사용 불가, 측정 범위 좁음, 반사면 취약 |
| 대표 제품 | Intel RealSense SR300, Orbbec Astra |

> **표 3-4.** 구조광 방식 특성

**[(3) LiDAR 센서]**

레이저 기반의 정밀 거리 측정이 가능하나, 단가가 높고(수백만 원~) RGB 정보를 별도 카메라와 융합해야 하는 제약이 있다. 주로 자율주행 차량, 측량 분야에서 활용되며, 제조 현장의 부품 인식 용도로는 비용 대비 효용이 낮다.

#### 3.1.3 센서 유형 선정 결론

본 과제에서는 부품의 외관(RGB)과 형상(Depth)을 동시에 활용하는 RGBD 4채널 기반 분류 모델을 설계하였으므로, **RGB-D 카메라(스테레오 비전 방식)** 를 핵심 센서로 선정하였다. 스테레오 비전 방식은 제조 현장의 대형 금속 부품 촬영에 적합한 원거리 측정 능력과 야외/실내 겸용 가능성을 갖추고 있으며, 최신 AI 기반 깊이 보정(Neural Depth)을 통해 텍스처 없는 금속 표면의 한계를 극복할 수 있다.

카메라 프레임 캡처, 녹화, 프레임 추출, 블러 필터링을 통합 관리하는 핵심 모듈이다. 스레드 기반 비동기 캡처로 웹 서버의 요청 처리와 카메라 프레임 획득을 분리하여, UI 응답성을 유지하면서 연속적인 프레임 캡처를 수행한다.

| 기능 | 메서드 | 설명 |
|------|--------|------|
| 초기화 | `__init__()` | ZED SDK 초기화 (HD1080, 30fps, Neural Depth), OpenCV 폴백 |
| 프레임 캡처 | `_capture_loop()` | 백그라운드 스레드에서 RGB+Depth 동기화 캡처 |
| 프레임 획득 | `get_frame()` / `get_depth()` | 최신 RGB/Depth 프레임 반환 (thread-safe) |
| 녹화 시작 | `start_recording()` | N 프레임 간격 자동 추출, 블러 필터링 적용 |
| 녹화 종료 | `stop_recording()` | 추출 결과 통계 반환 (총 프레임, 추출 프레임) |
| 수동 캡처 | `snapshot()` | 현재 프레임 1장 즉시 저장 |

> **표 4-1.** CameraManager 주요 기능

**[신호처리 흐름]**

```
ZED SDK grab()
    │
    ├─► retrieve_image(VIEW.LEFT) ──► BGRA→BGR 변환 ──► RGB 프레임
    │
    └─► retrieve_measure(MEASURE.DEPTH) ──► NaN/Inf→0 치환
                                           ──► float32→uint16 변환
                                           ──► Depth 프레임 (mm)
    │
    ├─► 녹화 모드 시: N 프레임마다 블러 검사
    │       │
    │       ├─► Laplacian Variance ≥ 100 → 저장 (양호)
    │       └─► Laplacian Variance < 100 → 폐기 (흐릿)
    │
    └─► 저장: RGB → frame_NNNN.png (8-bit)
              Depth → frame_depth_NNNN.png (16-bit, mm)
```

> **그림 4-2.** 신호처리 흐름도

**[품질 필터링 — Laplacian Variance 기반 블러 감지]**

비디오 스트리밍 방식으로 프레임을 추출할 때, 카메라 이동 중 발생하는 모션 블러(motion blur) 이미지를 자동 제거하기 위해 Laplacian Variance 기법을 적용하였다. 이 기법은 이미지의 2차 미분(Laplacian)을 계산한 후 그 분산(variance)을 구하여, 분산이 낮을수록(=고주파 성분이 적을수록) 흐릿한 이미지로 판단한다.

| 파라미터 | 값 | 설명 |
|---------|-----|------|
| 커널 | Laplacian (3×3) | cv2.Laplacian(gray, cv2.CV_64F) |
| 지표 | Variance | Laplacian 결과의 분산값 |
| 임계값 | 100 | 100 미만 = 흐릿 → 자동 폐기 |
| 적용 시점 | 프레임 추출 시 | 녹화 중 N 프레임 간격으로 적용 |

#### 4.1.5 OpenCV 폴백 지원

ZED SDK가 설치되지 않은 개발 환경에서도 시스템을 테스트할 수 있도록, OpenCV 웹캠 기반 폴백(fallback)을 구현하였다. 폴백 모드에서는 RGB 프레임만 제공되며 Depth는 None을 반환한다. 학습 파이프라인에서는 Depth 부재 시 0으로 채워(zero-fill) graceful degradation을 지원한다.

### 4.2 수집된 신호 데이터의 효율적 저장/관리를 위한 DBMS 스키마 설계

#### 4.2.1 설계 배경 및 목적

부품 인식 AI 시스템의 운영 과정에서 발생하는 데이터(이미지, 메타데이터, 학습 이력, 평가 결과)가 지속적으로 증가함에 따라, 체계적이고 효율적인 데이터 관리 체계가 필요하다. 본 연구에서는 대용량 이미지 바이너리 파일은 파일시스템에 저장하고, 메타데이터·학습 이력·평가 결과는 관계형 데이터베이스(RDBMS)로 관리하는 **하이브리드 저장 구조**를 설계하였다.

#### 4.2.2 설계 원칙

| 원칙 | 설명 |
|------|------|
| 하이브리드 저장 | 이미지는 파일시스템, 메타데이터는 RDBMS — 저장 효율과 관리 편의성 동시 확보 |
| 이력 관리 | 촬영 세션 → 이미지 → 학습 → 평가의 전체 생애주기 추적 |
| 확장성 | 새로운 부품 클래스, 센서, 모델 아키텍처 추가 시 스키마 변경 최소화 |
| 데이터 무결성 | 외래 키 제약 및 CHECK 제약을 통한 일관성 보장 |

> **표 4-4.** DBMS 스키마 설계 원칙

#### 4.2.5 핵심 테이블 DDL

**[datasets 테이블]**

```sql
CREATE TABLE datasets (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            VARCHAR(200) NOT NULL UNIQUE,
    type            VARCHAR(20)  NOT NULL
                    CHECK (type IN ('real', 'synthetic', 'mixed')),
    description     TEXT,
    num_classes     INTEGER NOT NULL DEFAULT 0,
    total_images    INTEGER NOT NULL DEFAULT 0,
    base_path       VARCHAR(500) NOT NULL,
    background_mode VARCHAR(20),
    created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**[images 테이블]**

```sql
CREATE TABLE images (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    class_id        INTEGER NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    session_id      INTEGER REFERENCES capture_sessions(id),
    rgb_filename    VARCHAR(50)  NOT NULL,
    depth_filename  VARCHAR(50),
    rgb_path        VARCHAR(500) NOT NULL,
    depth_path      VARCHAR(500),
    width           INTEGER NOT NULL,
    height          INTEGER NOT NULL,
    channels        INTEGER NOT NULL DEFAULT 4,
    depth_unit      VARCHAR(10) DEFAULT 'mm',
    depth_bit       INTEGER DEFAULT 16,
    blur_score      REAL,
    data_source     VARCHAR(20) NOT NULL
                    CHECK (data_source IN ('camera', 'isaac_sim', 'augmented')),
    is_valid        BOOLEAN NOT NULL DEFAULT TRUE,
    split           VARCHAR(10) CHECK (split IN ('train', 'test', 'val')),
    captured_at     TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(class_id, rgb_filename)
);
```

## 5. 부품 인식 AI 학습용 기초 데이터셋 구축

### 5.1 부품 인식 학습을 위한 모사 시험 환경 구축

#### 5.1.1 구축 배경

굴착기 도어 부품은 실물 확보가 제한적이며(종류당 1장), 다양한 시점·조명·배경 조건의 학습 데이터를 대량으로 확보하기 어렵다. 이러한 제약을 극복하기 위해, **NVIDIA Isaac Sim** 기반의 디지털 트윈 모사 시험 환경을 구축하여 CAD 모델로부터 합성 RGBD 데이터를 자동 생성하는 파이프라인을 개발하였다.

#### 5.2.4 통일 전처리 파이프라인

실물·합성 데이터 모두 동일한 전처리를 거쳐 모델에 입력된다. 전처리 로직은 `depth_utils.py` 모듈로 공통화하여, 모든 학습·평가·추론 스크립트에서 일관된 처리를 보장한다. 특히, 부품의 종횡비가 분류 핵심 특징이므로 **Letterbox 방식**을 적용하여 장변 기준 축소 + 검정 패딩으로 종횡비를 완전히 보존한다.

| 단계 | RGB 처리 | Depth 처리 | 동기화 |
|------|---------|-----------|--------|
| 1. 로드 | PIL.Image (RGB) | cv2.imread (UNCHANGED, 16-bit) | - |
| 2. Letterbox Resize | 장변 448px, BILINEAR | 장변 448px, INTER_NEAREST | 동일 크기, 종횡비 보존 |
| 3. 중앙 배치 패딩 | 검정(0) 패딩 → 448×448 | 검정(0) 패딩 → 448×448 | 동일 영역, 정보 손실 없음 |
| 4. [학습] HorizontalFlip | np.fliplr (50% 확률) | np.flip axis=1 (50% 확률) | 동일 반전 |
| 5. [학습] Rotation | PIL rotate(±15°) | cv2.warpAffine(±15°, INTER_NEAREST) | 동일 각도 |
| 6. [학습] Scale | cv2.warpAffine(0.9~1.1, 50%) | cv2.warpAffine(0.9~1.1, INTER_NEAREST) | 동일 스케일 |
| 7. [학습] 색상·노이즈 증강 | Brightness/Contrast/Saturation/Hue/Noise/Blur | 미적용 | RGB만 |
| 6. 정규화 | ImageNet mean/std | ÷5000→[0,1]→(x-0.5)/0.25 | 개별 적용 |
| 7. 결합 | torch.cat([RGB_3ch, Depth_1ch]) | → [4, 224, 224] | RGBD 통합 |

#### 5.3.2 1단계 — 온라인 증강 (학습 시 실시간)

매 에포크마다 학습 이미지에 랜덤 변환을 적용하여 실질적 데이터 다양성을 확대하였다. RGBD 4채널 데이터의 특성상, 공간 변환은 RGB와 Depth에 동일하게 적용하되 색상 변환은 RGB에만 적용하는 전략을 채택하였다.

| 증강 기법 | 적용 대상 | 파라미터 | 확률 | 목적 | 비고 |
|----------|----------|---------|------|------|------|
| HorizontalFlip | RGB + Depth | 좌우 반전 | 50% | 좌우 시점 다양성 | 동일 반전 적용, 비대칭 부품 안전 |
| RandomRotation | RGB + Depth | ±15° | 100% | 회전 불변성 확보 | 동일 회전 행렬 적용 |
| RandomScale | RGB + Depth | 0.9~1.1배 | 50% | 카메라 거리 변화 시뮬레이션 | 동일 스케일 적용 |
| AdjustBrightness | RGB만 | factor: 0.6~1.4 | 100% | 밝기 변화 대응 | Depth 거리값 보존 |
| AdjustContrast | RGB만 | factor: 0.6~1.4 | 100% | 대비 변화 대응 | Depth 거리값 보존 |
| AdjustSaturation | RGB만 | factor: 0.7~1.3 | 100% | 채도 변화 대응 | Depth 거리값 보존 |
| AdjustHue | RGB만 | ±0.05 | 100% | 색조(색온도) 변화 대응 | Depth 거리값 보존 |
| GaussianNoise | RGB만 | σ: 3~10 | 30% | 센서 노이즈 대응 | Depth 거리값 보존 |
| GaussianBlur | RGB만 | kernel: 3 | 20% | 촬영 포커스 변화 대응 | Depth 거리값 보존 |

> **표 5-8.** 온라인 증강 기법 상세

> **RGBD 동기화 핵심**: Depth 채널은 물리적 거리(mm)를 나타내므로, 색상·노이즈·블러 증강을 적용하면 실제 거리 정보가 왜곡된다. 따라서 이들 증강은 RGB 3채널에만 적용한다. 공간 변환(반전, 회전, 스케일) 시 Depth에는 `INTER_NEAREST` 보간법을 사용하여, 보간에 의한 거리값 왜곡을 방지한다. 수평 반전은 도어 LH_FRT/LH_RR/RH의 내부 구조(격자 패턴, 힌지, 보강재)가 비대칭이므로 클래스 혼동 없이 적용 가능하다.

#### 5.3.6 2단계 계층적 분류 전략 실험 및 폐기 (Hierarchical Classification)

CAD 합성 데이터의 특성을 활용한 2단계 계층적 분류 전략을 실험하였다. 8개 클래스를 한 번에 분류하는 대신, 형상이 확연히 다른 3개 모양 그룹(LH_FRT, LH_RR, RH)으로 먼저 분류한 후, 각 그룹 내에서 미세한 크기 차이를 갖는 기종(E25, E30, E38)을 고해상도(960×960) 입력으로 분류하는 방식이다. **그러나 실험 결과 Step 2의 정확도가 매우 낮아, 본 접근법은 폐기하였다.**

**[2단계 분류 구조]**

```
2단계 계층적 분류
══════════════════════════════════════════════════════════

  입력 RGBD 이미지
        │
        ▼
  ┌─────────────────────────────────────────┐
  │ Step 1: 모양 분류 (Shape Classification) │
  │ · 입력: 448×448                          │
  │ · 출력: LH_FRT / LH_RR / RH             │
  │ · 형상 차이가 크므로 높은 정확도 기대     │
  └────────────┬────────────────────────────┘
               │
     ┌─────────┼─────────┐
     ▼         ▼         ▼
  LH_FRT    LH_RR      RH
     │         │         │
     ▼         ▼         ▼
  ┌────────┐ ┌────────┐ ┌────────┐
  │Step 2a │ │Step 2b │ │Step 2c │
  │E25/E30 │ │E25/E30 │ │E25/   │
  │/E38    │ │/E38    │ │E30_E38│
  │960×960 │ │960×960 │ │960×960│
  └────────┘ └────────┘ └────────┘
```

> **그림 5-5b.** 2단계 계층적 분류 구조

| 단계 | 목적 | 입력 크기 | 분류 대상 | 비고 |
|------|------|---------|----------|------|
| Step 1 | 모양(Shape) 분류 | 448×448 | LH_FRT, LH_RR, RH | 3클래스, 형상 차이 뚜렷 |
| Step 2a | LH_FRT 내 기종 분류 | 960×960 | E25, E30, E38 | 가로 차이: 828/869/916mm |
| Step 2b | LH_RR 내 기종 분류 | 960×960 | E25, E30, E38 | 3클래스 |
| Step 2c | RH 내 기종 분류 | 960×960 | E25, E30_E38 | 2클래스 (E30/E38 통합) |

> **표 5-8b.** 2단계 분류 단계별 설정

**[고해상도 입력의 근거]**: Step 2에서 960×960 이상의 고해상도를 사용하는 이유는, 동일 모양(예: LH_FRT) 내에서 E25(828mm), E30(869mm), E38(916mm)의 가로 크기 차이가 40~50mm에 불과하여, 낮은 해상도에서는 픽셀 수준의 차이가 소멸되기 때문이다. 고해상도 입력을 통해 이러한 미세한 비례 차이를 보존할 수 있을 것으로 기대하였다.

**[실험 결과 — 실패]**

CAD 합성 데이터 4,000장(8클래스×500장)으로 2단계 분류를 학습한 결과, Step 1(모양 분류)은 완벽하였으나 Step 2(기종 분류)에서 심각한 성능 저하가 관찰되었다.

| 단계 | 대상 | 정확도 | 비고 |
|------|------|--------|------|
| Step 1 (모양 분류) | LH_FRT / LH_RR / RH | **100.0%** | 형상 차이가 뚜렷하여 완벽 분류 |
| Step 2 LH_FRT | E25 / E30 / E38 | **33.3%** | 3클래스 랜덤 수준, 학습 실패 |
| Step 2 LH_RR | E25 / E30 / E38 | **100.0%** | 유일하게 성공한 그룹 |
| Step 2 RH | E25 / E30_E38 | **69.0%** | 2클래스인데도 부진 |
| **Cascade 최종** | **8클래스** | **67.2%** | 실용 불가 수준 |

> **표 5-8c.** 2단계 계층적 분류 실험 결과 (CAD 데이터)

**[실패 원인 분석]**

1. **픽셀 기반 크기 구별의 한계**: 960×960 해상도에서도 40~50mm의 물리적 크기 차이는 CNN이 학습하기에 너무 미세하다. 도메인 랜덤화로 카메라 거리·각도가 매번 달라지므로, 동일 부품도 이미지상 크기가 크게 변동하여 비례 차이가 희석된다.
2. **보조 피처(Auxiliary Features) 부재의 영향**: 단일 단계 분류(`02_door_cad_classification_5090.py`)에서는 Depth 기반 `compute_aux_features`가 물리 치수(mm)를 수치 피처로 직접 제공하여 40~50mm 차이를 명시적으로 전달한다. 2단계 방식은 이를 CNN 픽셀 학습에만 의존하여 핵심 분류 단서를 활용하지 못했다.
3. **CAD 데이터의 텍스처 부재**: 실물 데이터와 달리 CAD 렌더링은 재질·조명·그림자 패턴의 다양성이 부족하여, 크기 외의 외관 특징이 학습되지 않는다.

**[결론 및 폐기 사유]**

본 실험을 통해, **유사 형상 부품의 크기 차이는 CNN 픽셀 패턴이 아닌 Depth 기반 물리 치수 보조 피처(Auxiliary Features)로 구별하는 것이 유효**함을 확인하였다. 2단계 계층적 분류 스크립트(`02_door_cad_classification_5090_2step.py`)는 `deprecated/` 폴더로 이동하여 보관하며, 향후 개발에서는 단일 단계 분류 + 보조 피처 방식을 유지한다.
